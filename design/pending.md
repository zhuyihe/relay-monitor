# 待改总表

规范接下来要改什么，各由哪个 PR 改。这里只列编号、去处和 PR；条目原文在各设计稿里。

怎么维护（[CONTRIBUTING](../CONTRIBUTING.md) 第 1 节）：

- 用语规范里，「（新）」是已经定了、代码还没做的说法；「（旧）」是已经定了要换掉、代码还在用的说法。
- 每一行随哪个 PR 做或换，只记在这里，规范的标记里不写 PR 名。
- 一句字随哪个 PR 换，看哪个 PR 删掉或重写显示它的那个组件。K2c 只改接口，屏幕上的字一个不换。
- 做的那个 PR 去掉「（新）」，或者删掉「（旧）」那一行，连同这里对应的那一行，和代码一起合并。
- 设计稿的拟改条目进了规范，这里那一行也删掉。
- 「推断」是按开发的方案和流程梳理稿推的，「待定」是哪里都还没写明，都等开发、设计核对。

PR 代号：C2a–C3 是结账可靠性，K1a–K2d 是认 Key、渠道跟着 Key 走（[流程梳理稿](./ux/binding-flow.md)），D、E、F、G、第一次使用、合页见[总目录](./README.md)里各份设计稿。
