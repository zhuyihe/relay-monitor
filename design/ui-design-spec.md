# 炬元控制台 · UI 设计规范与改版方案

> 对应问题清单见 [ui-audit.md](./ui-audit.md)；可交互高保真稿见 [mockups/index.html](./mockups/index.html)。
> 本方案是**演进而不是重做品牌**：保留钴蓝主色、深色侧栏和品牌标记，重做的是信息组织、令牌体系和数据表达。
> **页面上的用语一律以 [ui-copy-spec.md](./ui-copy-spec.md) 为准。**本文的线框图和例句如与它不一致，以它为准；页面名以 `lib/brand.js` 为准。

## 0. 这个产品在回答什么

使用者是自己经营 AI API 转售业务的运营者，一天会打开控制台很多次，其中不少是在手机上。每次打开，他想在 5 秒内知道三件事：

1. **今天赚没赚钱**——收入减去上游成本和固定成本，还剩多少。
2. **哪个上游快没钱了**——按现在的花费速度还能用几天。
3. **有没有必须我处理的事**——读不到余额、快到期、利润需处理。

现状把这三件事分散在 4 个页面、几十张卡片里。改版的全部取舍都服务于这三个问题。

## 1. 设计原则

分三组：§1.1 管页面看起来怎么样，§1.2 管用户要做多少事、按什么顺序做，§1.4 管一页放什么、怎么排、空间怎么用。每份设计稿和每个页面改动都要对照这三组写清「为什么」（§1.3）；审核也按这三组逐页过。

### 1.1 视觉原则

1. **等式即界面。**利润就是一道减法，那就把减法直接画出来，分两行：`收入 − 上游成本 = 毛利`，`毛利 − 固定成本 = 净利`。这是本产品唯一的“招牌”元素。完整的等式只放运营总览（今天）和每日利润（按天、按渠道）两处的首屏；自营业务只放收入那一半和一行毛利，成本估算只放成本那一半（2026-10-24 定，ui-audit §8.4 第 3 件，G 实现）。除此之外的一切保持安静。
2. **颜色只说一件事。**状态色（正常/注意/紧急）只表示状态，并且永远配图标和文字；系列色只表示“这是哪条数据”；金额本身一律用正文墨色。“正数就是绿色”这种规则取消。
3. **报数据时间，不报拉取时间。**每一组数字都标明它是哪个时刻的数据（“数据截至 14:32”），而不是页面何时请求了接口。
4. **不确定就明说。**数据不完整时用 `≈` 前缀、斜纹占位和一句原因说明，不用红色吓人；未配置是引导，不是报错。

### 1.2 交互和流程原则

2026-10-24 用户定的方向：「尽量减少不必要的操作」「能把整个流程串起来，而不是零零碎碎的拼接」「要化繁为简」。下面七条是它的具体做法。

1. **系统能知道的，不问。**
   - 能从自营站点、上游读到或推出来的东西，系统自己匹配、自己填好，用户只看结果：渠道用的是哪把 Key、它属于哪个上游账号和分组、倍率、按哪个时区算一天、余额是什么币种。
   - 正：测试读取以后自动带出上游账号名和余额，用户不用自己填。
   - 反：渠道绑定要用户在「这些渠道用的 Key」下拉里自己挑 Key；系统其实能从渠道里读到（K 设计稿要去掉）。
   - 审核时：把页面上每个输入框、下拉、单选列出来，逐个问「系统能不能读到或推出来」。能，就是问题。
2. **手工只做两件事：确认、更正。**
   - 默认的路上没有「请选择」。自动的结果可能错时，就在结果旁边给更正入口（「指定 Key」「改时间」），不另开页面、不换页签。
   - 正：K 设计稿里「用过的 Key」每一段旁边就是「改时间」，认不出的一段旁边就是「指定 Key」。
   - 反：现在「换 Key」要跳到渠道绑定页签，先解除绑定，再从头绑一遍。
   - 审核时：沿默认的路数「请选择」，应该是 0；每个自动结果离它的更正入口不超过一次点击。
3. **只问系统不可能知道、又会改变钱的事，一次问清，不预先选好答案。**
   - 例如「这个上游账号只给你自己的渠道用吗」：系统看不出来，又决定利润算不算。按账号问一次，不按 Key、不按渠道反复问。
   - 预先选好的答案等于替用户答了，用户不知道自己「答」了什么。
   - 正：账号的问题在渠道绑定里就地问，一个账号只问一次（K 设计稿第 5 节）。
   - 反：以前每条绑定都问「这把 Key 还给别处用吗」，还默认选好「不确定」（体检 §7.2，#56 已改）。
   - 审核时：每个问题过三关：系统真的不知道吗？答案会改变钱吗？是不是已经在别处问过？三关都过才留，而且一开始不选。
4. **一个目标一条路，从头走到尾。**
   - 接入上游、开始算利润、处理一件需处理，每个目标是一条连贯的流程：每一步告诉用户下一步是什么，做完落到用户最想看的地方。
   - 不让用户自己在几个页签之间拼。
   - 正：需处理里的「测试读取」「去回答」「重新读取」就地做完，清单当场少一条（E 设计稿）。
   - 反：接入一个上游以后，要自己想到去「渠道绑定」页签绑渠道，再去「每日利润」看结果，中间没有一句话告诉他。
   - 审核时：拿一个目标从入口走到终点，记下换了几次页签、回头几次、有几步没告诉下一步；做完落在哪。
5. **先结论，后细节。**每页先回答这一页最重要的问题，细节收起来；同一件事只在一处说。版式上怎么做、正反例和审核时怎么查，见 §1.4 第 1、2 条。
6. **少打扰。**
   - 只有「不处理就算不准」的事才进需处理、才打断用户。
   - 系统自动做的事安静做完，记在时间线和改动记录里，查得到。
   - 正：系统发现换了 Key，只在「用过的 Key」多一行（K 设计稿第 4 节）；7 天内的读取类问题只写「还在读取」，不进需处理（§4、D2）。
   - 反：第一次打开，需处理里全是不影响钱的「测试读取」（体检 §7.8）。
   - 审核时：每个弹窗、提示条、需处理的一条、推送都问：不处理的话，哪个数会算错？答不出来就不该打扰。
7. **每个设计都要说「为什么」。**
   - 每份设计稿、每个页面改动都写清（§1.3）：用户目标是什么、为什么这样设计、省掉了哪些操作、对照了哪几条原则。
   - 审核也按 §1.1、§1.2、§1.4 逐页过。

### 1.3 设计稿和页面改动要写的

每份设计稿（`design/ux/*.md`）开头，和每个改页面的 PR 说明里，都写这几项：

| 项 | 写什么 |
|---|---|
| 用户目标 | 用户想做成什么，用用户的话说 |
| 流程 | 从哪里进、一步步到哪里结束；改之前和改之后各几步、换几次页签 |
| 省掉了什么 | 哪些选择、点击、跳转，改成了系统自己做 |
| 还要用户做的 | 剩下的每一步，是确认、更正，还是 §1.2 第 3 条那种只有用户知道的问题 |
| 对照原则 | 用到了 §1.2、§1.4 哪几条；有违反的，写清为什么 |
| 版式 | 这一页回答什么问题；首屏放什么、收起或挪走什么；桌面 1440 怎么分栏、手机 390 怎么排（§1.4） |

### 1.4 页面版式和信息密度

2026-10-24 用户定的方向：「视觉要合理。不要什么东西都放在页面上。尽量多的利用页面的空间。每一个页面怎么设计」。下面九条是它的具体做法，和 §3（令牌）、§4（组件）、§5（每页蓝图）配合用：这里定规矩，那里定数值和样子。

1. **少而准：每页先定它回答什么问题。**
   - 首屏只放回答这个问题的结论和下一步；其余收起、点开再看，或者放进详情、抽屉。
   - 要收起的：计算明细、改动记录、用过的 Key 超过 3 段的部分、「数字怎么来的」、读不到的长原因。
   - 正：运营总览首屏就是利润等式、需处理、余量三块，回答「今天怎么样、有什么要我处理」。
   - 反：成本估算顶上「数字怎么来的」一大段字，手机上占满首屏（体检 §7.16）；用量分析读不到时，一整块黄底列着 5 个上游的原因，把用量表挤到第二屏。
   - 审核时：写下这一页回答的那个问题，只看首屏（桌面 1440×900、手机 390×844），能不能答出来？首屏上每一块都问「它在回答这个问题吗」，不是就收起或挪走。
2. **一页一个主角。**
   - 最重要的数或表最显眼（最大、最靠上、最宽）；次要的降级：字小一号、灰色、收起，或者挪到侧栏那一栏。
   - 同一个数、同一句话，一页只出现一次。
   - 正：利润等式的净利那一格放大加底色，其余几格小一号。
   - 反：每日利润页上汇总、横条、绑定列表都在说「有几天需处理」，几句话还互相打架（体检 §7.12）；运营总览等式下面一长句把所有没设置汇率的上游名字连起来，比等式本身还占地方（体检 §7.16）。
   - 审核时：遮住页面，只看一眼，说出最先看到的东西；它应该是这一页的主角。再把页面上的数字和句子各数一遍，有重复的就删到一处。
3. **用好空间。**
   - **桌面宽屏（1440 及以上）按内容分栏，用 12 列栅格**：主角占 8 列、旁边 4 列放相关的次要块（例如需处理、可用天数）；两块同样重要时各占 6 列。
     - 不要一列窄内容、两边大片空白。
     - 不要一张卡片撑满整行只放一个数或一个输入框：几个小设置并排放进同一块，指标并排成一行。
   - **同一行的两块，高度要接近**：主角那块不能被旁边撑出大块空白（超过一行字的高度就算）。做法按内容挑：
     - 旁边是列表的，按主角的高度只露前几条（例如运营总览的需处理，1440 宽时露 2 条，§5.1），其余写「还有 N 件」；
     - 旁边内容少的，把几小段上下叠放，或者并排放进去，不另起一行；
     - 两块都少，就合成一块。
   - **表格的列宽按内容定**：名字列给够、不截断，数字列按最长的数，说明类的列可以换行；不要每列平均分。
   - **手机 390 用单栏**，顺序就是首屏的结论在前、细节在后（运营总览「需处理」在等式前面，#56）；横排的指标改成两列小格，不横向滚。
   - 正：运营总览「需处理」和「上游余量」在宽屏上并排两栏。
   - 反：每日利润没设置自营站点时，一张小卡片孤零零放在一大片空白中间，像出错页（体检 §7.11）；系统设置「刷新与数据」「余额提醒线」两块各只有一个输入框和一个按钮。
   - 审核时：在 1440 宽下截一张整页，量主内容占了多少宽度；有没有一整行只放一个数或一个输入框的块；同一行两块的底边差多少；表格有没有被截断的名字、过宽的空列。手机下有没有横向滚动。
4. **说明文字默认一行。**
   - 面板标题旁的说明、输入框下的说明，默认一行；多出来的收进「展开」或「?」悬停。
   - 不在面板顶上写段落；规则性的长说明放进「怎么算的」这类收起区。
   - 正：每日利润「以前的每日记录」下面只有一行。
   - 反：新增上游表单里「这是我的自营站点」下面一大段说明（ui-audit §8.2 流程二）。
   - 审核时：数每块说明的行数（桌面宽度下），超过一行的问：能不能删短，或者收起？
5. **密度：给要扫读数字的人。**
   - 财务、运营要扫读数字：表格紧凑（行高 40，手机列表一项两行），数字用等宽数字、右对齐，同一列小数位一样。
   - 装饰让位给数：不用大图标、大插画、阴影卡片撑高度；颜色只说状态（§1.1 第 2 条）。
   - 一屏（桌面）至少能扫到 10 行表格。
   - 正：上游列表一行一个上游，余额、日均花费、可用天数三列对齐。
   - 反：上游账单每个上游一张大卡片，两行字配一排按钮，一屏只看得到三四个（体检 §7.16）。
   - 审核时：数桌面一屏能看到几行数据；数字列对没对齐、小数位一不一样。
6. **留白分组，不靠框。**
   - 层级靠三种底色和发丝线建立（§3.2、§3.5），不是给每块内容套一个带阴影的卡片。
   - 相关的东西靠近（块内 8–16），不相关的分开（块与块 24）；间距只用 §3.5 那几档。
   - 审核时：看有没有框套框、卡片里再套卡片；同一块里的东西间距是不是比块和块之间小。
7. **卡片还是表格。**
   - 同一类东西有好几个、要互相比较数字：表格（上游列表、每日利润的绑定）。
   - 一个对象有好几种操作、彼此不比：卡片（上游账单的一条绑定、手机上的一个上游）；放在窄栏里时一个一行（告警中心的通知方式：名字和开关、类型和测试结果、几个操作，彼此不比数字，§5.7）。
   - 只有一个数：不单独做卡片，放进指标行或等式里。
   - 只有「可以单独被操作的对象」才做成卡片（原 §1.1 第 3 条并到这里）。
   - 审核时：每张卡片问「它是一个能单独操作的对象吗」；同类卡片超过 5 张、又要比数字的，改成表格。
8. **空状态占它本来的位置。**
   - 没有数据时，一句说明加一个按钮（ui-copy-spec §8.1），放在内容本来的位置，大小和有数据时差不多；不撑满一屏，不像出错。
   - 还没设置的是引导：按钮直接打开设置（§1.2 第 4 条），不跳到别的页。
   - 正：运营总览「今天收入」没设置自营站点时，块里一句话加「去设置」。
   - 反：每日利润没设置时，整页中间一张红框卡片（体检 §7.11）。
   - 审核时：把每一块的空状态、读不到、还没设置三种样子各看一眼：是不是一句话一个按钮、是不是在原位、像不像出错。
9. **小窗还是抽屉。**
   - 只问一件事、一两个字段：小窗（去回答、指定 Key、确认框）。
   - 一件要填几样、要看结果的事：右侧抽屉（加上游、设置自营站点、开始算利润），提交按钮吸底。
   - 不在抽屉里再开抽屉；小窗里不放表格。
   - 手机上两种都从底部升起。
   - 审核时：数弹出层里的字段和步骤，一件事以上的用抽屉；有没有层套层。

## 2. 信息架构与导航

### 2.1 导航分组

侧栏从平铺 8 项改为 3 组，组名只作为分隔，不可点击：

| 分组 | 页面 | 路由 |
|---|---|---|
| 监控 | 运营总览 · 上游资源 · 用量分析 | `/` `/stations` `/usage` |
| 经营 | 自营业务 · 成本估算 · 每日利润 | `/my` `/analytics` `/reconciliation` |
| 系统 | 告警中心 · 系统设置 | `/notifications` `/settings` |

- 菜单项使用 Next `<Link>`，可在新标签页打开。
- 页面名以 `lib/brand.js` 为准（2026-10-16 确认：监控估算 → 成本估算、账单核算 → 每日利润，见 ui-copy-spec.md §11），改名只改这一处。
- 需要处理的数量以数字徽标显示在“运营总览”菜单项右侧（仅紧急+注意，>0 时显示）。

### 2.2 应用外壳

```
┌──────────┬────────────────────────────────────────────────────────────┐
│ ▌炬元     │ 运营总览                        数据截至 14:32   ⟳   ◐   管 │  ← 顶栏 56px，sticky
│          ├────────────────────────────────────────────────────────────┤
│ 监控      │                                                            │
│ ▎运营总览 3│   页面内容（最大宽度 1440，左对齐，左右留白 24）                │
│  上游资源  │                                                            │
│  用量分析  │                                                            │
│ 经营      │                                                            │
│  …       │                                                            │
└──────────┴────────────────────────────────────────────────────────────┘
```

- **补上桌面顶栏**（修复审计 V1）：左侧为页面标题 `h1`（顶栏即页头，不再在内容区重复一个 PageContainer 标题，从根本上消除 V2 标题截断）；右侧依次为数据时间、刷新、主题切换、账户菜单。
- 刷新按钮触发**当前页面**的数据重取（通过页面注册的 `onRefresh`），而不是只刷新外壳。
- 侧栏宽 232px，可折叠到 64px；折叠状态持久化到 `localStorage`。
- 移动端（<768px）：顶栏左侧为菜单按钮 + 页面标题，品牌标记使用深色版本（修复 V3/V4）；侧栏以抽屉形式出现，首帧不渲染（修复 V5）。

### 2.3 URL 即状态

时间范围、筛选、标签页、排序全部写入查询参数（`?range=7d&tab=users`），刷新和分享链接后状态不丢；跨页跳转用 `<Link href="/stations?status=attention">` 带上上下文。

## 3. 视觉基础

### 3.1 单一令牌来源

新建 `lib/design-tokens.js`，导出 `light` / `dark` 两组令牌对象，作为唯一来源：

- `providers.tsx` 用它生成 antd `theme.token` 与 `components`；
- antd v6 默认开启 CSS 变量（`--ant-*`），自定义 CSS 直接引用 `var(--ant-color-primary)` 等；
- 产品特有的少量变量（侧栏、图表系列、状态浅底）由 `providers.tsx` 以 `style` 注入到 `<html>`，命名为 `--jy-*`；

## 4. 组件模式

### 4.1 时间范围选择器 `<RangePicker>`

全站统一一个组件，替代 5 种写法（审计 §4）：

- 预设：`今天 · 近 7 天 · 近 30 天 · 近 90 天 · 自定义…`。页面可声明子集（总览只用前三项；分析页全部）。
- 选中即生效，没有单独的“查询”按钮（修复对账页预设不生效的问题）；自定义范围在弹层中确认后生效。
- 控件下方或旁边始终显示解析后的实际窗口：“9月18日 00:00 至 9月24日 14:32”。
- 写入 URL `?range=7d` 或 `?from=…&to=…`。

### 4.2 利润等式条 `<ProfitEquation>`

本产品的招牌组件。

```
收入              上游成本            毛利
¥1,248.60    −    ¥830.21       =    ¥418.39
较昨日 +12%        6 个上游            毛利率 33.5%

                  毛利                固定成本            净利
             ¥418.39       −    ¥40.00       =    ¥378.39
                                  按天平摊            净利率 30.3%
```

- 两行：第一行 `收入 − 上游成本 = 毛利`，第二行 `毛利 − 固定成本 = 净利`。运算符 `−` `=` 用细体墨·弱色，和数字同字号；数字用 `fs-hero`。
- 字号按等式这一块自己的宽度缩（容器查询，不看窗口宽度），只用刻度里的档：块宽 960 以上 `fs-hero` 32/40；960 以下 24/32（`fs-figure` 那一档）；760 以下 20/28（`fs-title` 那一档），格子左右内边距也收到 8。运算符、「没设置」「读不到」那种空格子跟着数字一起缩。运营总览 1440 宽时等式只占 8 列，是 20 号；成本估算、自营业务的等式占整行，窗口约 1290 以上是 32 号，再窄按同一条规则缩。
- 结果项“净利”放在钴·浅底上，是整条的视觉终点。
- 每一项可点击，跳到对应明细（收入 → 自营业务，上游成本 → 上游资源，固定成本 → 上游资源固定成本筛选）。
- **数据不完整**：缺失项显示斜纹底 + “部分数据缺失”，结果前加 `≈`，结果颜色保持墨色，并在下方给出原因（如“1 个上游读不到用量，它的成本没算进去”）。**不用红色。**
- **亏损**：结果显示为 `−¥12.40`，前缀状态图标“紧急”菱形 + 文字“亏损”；数字本身仍是墨色。
- 移动端纵向排列为账单式：每行一项，运算符在左列，结果项之上有一道 2px 横线。

### 4.3 待处理列表 `<AttentionList>`

替代总览中“余额偏低 N 个”计数和分散的动作卡片，口径统一。

- 每行：状态图标 + 对象名 + 一句话说明发生了什么 + 一个主操作 + 次操作链接。
- 排序：紧急 → 注意 → 信息，同级按预计耗尽时间。
- 空状态：“目前没有需要处理的事。数据截至 14:32。”
- 同一对象的多个问题合并为一行，列出最严重的一个，其他收入“另有 1 项”。

### 4.4 余量跑道 `<Runway>`

用“还能撑几天”替代“余额是多少”作为上游的主指标。

- 水平条长度 = 预计可用天数（刻度 0–14 天，超过 14 天封顶并显示实际值）。
- 条上两条刻度线分别为“注意”和“紧急”的提醒线，**读取告警设置 `etaDays`，不写死 3/7**。
- 条颜色：正常为墨·弱色；进入注意/紧急区间才使用状态色，并在数值旁加图标和文字。
- 旁边显示余额与日均花费；读不到余额时条变为空心虚框，显示“读不到余额”。
- 手机（< 768）上一项占两行：第一行写上游全名（不截断，太长就换行），右边是天数和档位；第二行是条。刻度行跟着只占一列。横向条形（今天上游成本等）在手机上也一样，名字一行，条和数值在下一行。

### 4.6 数据状态 `<DataState>`

所有页面共用一套：

| 状态 | 表现 |
|---|---|

### 4.7 表格

- 所有密钥（访问令牌、API 密钥、Bot Token、Webhook、SMTP 密码）使用 `Input.Password`，`autoComplete="new-password"`；编辑时占位符显示“已保存”，下方说明“留空则继续使用已保存的令牌”；输入新值后说明改为“保存后替换原来的令牌”。

### 4.11 收起区 `<More>`

（§4.10 留给 F 设计稿的日条。）说明文字、读不到的列表、明细，默认收起，按 §1.4 第 1、4 条：

- 收起时只露一行：一句结论（例如「5 个上游的用量读不到，合计里不含它们」）+ 一个文字按钮，按钮写它收着什么（「看原因」「数字怎么来的」），后面一个向右的箭头；展开后箭头朝下。
- 按钮写它收着什么，是名词短语，不受 ui-copy-spec §2 第 7 条「按钮用动词开头」的约束；不写「展开」「收起」，箭头已经说了。
- 默认收起。只有收着的内容就是这一页要说的事时才默认展开（例如用量分析全部上游都读不到时的原因）。
- 没有可收的东西时不出按钮，只留那句结论（例如成本估算没有缺记录时，不再给「哪些天、哪些上游缺记录」）：按钮名不能和结论矛盾。
- 按钮是 `<button aria-expanded>`，展开的内容紧跟在它下面，不弹层、不挪页面其他部分。手机上（767 以下）按钮点的地方至少 44 高。
- 页面里有链接指向收起区（例如「查看没算进去的数据」）时，点链接要展开它并滚过去；带着这个 # 打开或刷新页面时也一样。`<More anchor>` 写的是页面上那一块的 id，要滚到的那一块自己带这个 id。
- 页面要控制开合时（例如开合状态从外面传进来、定位到某一项时要由程序展开），给 `More` 传 `open`／`onOpenChange`（受控用法，版式 PR 4 加的），不另写一套；不传 `open` 时它自己管。一旦传了 `open` 就一直传，不在两种用法之间来回换。
- 收着的内容里有会把它收起的按钮（「取消」「保存」）时，用 `buttonRef` 拿到收起区的按钮，收起以后把焦点还给它（自营业务「选转售 Key」），不然焦点落在已经不在的按钮上。
- 用法写在 `app/components/more.tsx` 一处，各页不各写一份；结论和按钮要排在同一行时，外面那一层加 `jy-more-line`（`app/styles/jy.css`）。运营总览需处理的「还有 N 件」也是它（版式 PR 3 换过来的）。
- 报错原文不用它，用 ui-copy-spec §8.2 的「查看详细原因」（`app/components/error-detail.tsx`）。

```
│ 拼车团队   ████         约 22 天     │  alice ███  bob ██ …     │

│                                      │  主力 ███  邮箱 ██ …     │
└──────────────────────────────────────┴──────────────────────────┘
```

- 栅格用 jy.css 的 `.jy-grid-8-4`（主角 8 列、旁边 4 列；1200 以下叠成一列）。以后 8 + 4 的页都用它，不各写一份。同一行的两块拉成一样高。
- 第一行：利润等式 8 列 + 需处理 4 列。需处理露几条按等式那块的高度定（§1.4 第 3 条：主角那块被旁边撑出的空白不超过一行字）：1440 宽时露 2 条（最要紧的在前），其余收进「还有 N 件」；等式变矮（G 把「≈」说明收成一行）以后按同一条规矩再调。等式的金额字号按等式这一块自己的宽度缩（§4.2，只用刻度里的档），五位数带「≈」「−」的金额也不压到运算符；1440 宽的运营总览是 20 号。点开「还有 N 件」以后这一行不再拉成一样高，等式那块照自己的高度。用收起区 `More`（§4.11），点开在原地列出其余几条；没有收起的时候，最下面照旧一句「其余 N 个上游没有要处理的事」。
- 第二行：上游余量 8 列 + 「今天收入和上游成本」4 列。收入、上游成本合成一块，上下两小段「收入 · 按用户」「上游成本 · 按上游」，各列前 3 名，多的并成「其他 N 位用户」「其他 N 个上游」一行。小段标题不带合计、也不再有单独的「合计」一行：收入、上游成本的合计只在利润等式里出现（§1.4 第 2 条，总指挥定，不开例外）。没设置自营站点、收入读不到、利润算不出时，原因和按钮只放在等式下面那一处；小段里只写一句短状态（「读不到，原因见上面的利润等式。」，ui-copy-spec §11），不带按钮，同一句话一页只说一次。手机上这一块也在等式下面，「见上面」说得通。
- 数据多的时候（上游、用户上百个）：页面高度不跟着涨。需处理首屏固定 2 条，其余在「还有 N 件」里，点开才渲染；上游余量最多 8 行；收入和上游成本每段前 3 加一行「其他 N …」。点开「还有 N 件」一次列出全部，上百条时的分页随 E 的需处理清单定。
- 手机（< 768）：需处理在前（#56），然后利润等式、上游余量；「收入和上游成本」那块的条形收进「按用户、按上游看」（`More`，默认收起；只有一段有条形时写「按用户看」或「按上游看」，收入在前、上游成本在后）；没设置自营站点、读不到、算不出、这段时间没有收入这类一句话的状态照样露在外面。
- 删除与“上游资源”重复的完整站点列表，由“上游余量”+ 链接替代。
- 总余额移入“上游余量”面板标题：“可用余额合计 ¥2,357.75（不含 1 个读不到余额的上游）”。
- 轮询间隔读取设置中的 `refreshIntervalSec`；页面不可见时暂停。

### 5.2 上游资源 `/stations`

- 工具栏：搜索（名称/地址）、状态分段 `全部 · 需处理 · 正常 · 已归档`、类型筛选、排序、`添加上游`（移动端也可用）。
- 表格列：上游｜状态｜余额｜日均花费｜可用天数｜操作（#64 第 2 节、§1.4 第 5 条）。一行最多两行字、行高 56 以内，桌面一屏看得到 10 行以上；56 优先于把名字写全：
  - 上游：上一行名称和标签，标签不折行，放不下时名称省略、悬停和读屏看全；下一行地址 · 账号名，放不下的省略。点名称打开编辑。
  - 状态：只放状态，不放链接、按钮。上一行是余额档位、固定成本的状态（读不到余额也是档位）；没有档位、只有要处理的事（利润类、账号类）时写「需处理」，几件事时写「需处理 · 还有 N 个问题」（N 是第一件以外的件数）；有档位又有要处理的事时写「余额偏低 · 还有 N 个问题」（N 是事的件数，档位本身不算）。下一行按先后只放一样：「正在刷新」；数据旧时的「数据截至 14:20」；有档位时，这个档位的说明（「低于提醒线 $5」「按现在的花法，3 天以内就会用完」，ui-copy-spec §3.3；读不到余额的行这里不写，原因在下面那一行）——这时事的标题不写在这里，写在行末那件事的按钮上：鼠标悬停、键盘聚焦都显示提示「测试读取：还没确认…」，读屏念同一句（aria-describedby），按钮名本身不带标题；平板触屏看不到这个提示，状态格写着「还有 N 个问题」、点按钮打开的抽屉里有原因；档位自己没有说明时（「还没读取」、部分固定成本状态），退回写事的标题；没有档位时，要处理的那件事的标题；状态自己的说明（「不再续费，不再提醒」「要续上，再记一笔固定成本」）。版式 PR 5 改：以前有档位时下一行写的是事的标题，读起来像在解释档位。不重复同一行可用天数一格里的天数。放不下的省略，悬停和读屏看全；小钟和「后面几次刷新都没读到」那句只跟「数据截至」走。
  - 余额：上一行近 48 小时的小图在左、余额在右（没有小图的行留同样宽的空位，金额上下对齐）；下一行「约 ¥88.56」或「没设置汇率」。
  - 日均花费：上一行「≈ ¥1.30」，按哪段花费估的（「按近 12 小时的花费估算」）放进悬停和读屏；下一行「今天花费 ¥2.58」。固定成本的说明不折行，放不下省略。
  - 不再有「数据截至」一列：每行都是同一个时刻，顶栏已经写了。某个上游的数据比服务端此刻（上游列表的接口一起返回）旧「2 × 刷新间隔 + 30 秒」以上时（30 秒是单次读取超时的余量），在它的状态格下一行写「数据截至 14:20」，前面一个小钟。只用服务端的时钟，不拿浏览器的时钟比；所有上游都旧了（后台刷新卡住）、只有一个上游时也照样标。测试读取不写库：成功后不改读取时刻，那一行在下一次刷新列表之前不标「数据截至」（显示的是刚读到的余额）。读不到余额的上游下面另有一行说原因，不再标。
  - 操作：有要处理的事时，行末的按钮就是那件事（例如「测试读取」），「编辑」挪进「⋯」，点名称也能编辑；没有时行末是「编辑」。一行有几件事时，第一件放行末，其余进「⋯」的最上面，写成「按钮名：标题」（例如「测试读取：还没确认能读到这个上游的完整账单」）。
  - 默认排序按需要关注的程度：档位和那几件事里最严重的那个。
- 手机上一个上游一张卡片，按 §4.7 两行：上一行名称、状态、「⋯」；下一行余额 · 可用天数（#64 第 2 节）。余额设了汇率只写金额（换算在悬停里）；没设置汇率照旧写「¥12.30（没设置汇率）」，不能让人当成人民币。固定成本的上游写日均花费 · 还剩几天。数据比别的旧、正在刷新时，第二行带「数据截至 14:20」「正在刷新」，放不下时折行。有要处理的事时多一行：那件事的标题（放不下省略）和它的按钮（最右边）；不挤进第二行，挤进去标题只剩两三个字。小图和「刷新」「编辑」「余额趋势」都在「⋯」里，点名称也能编辑。
- 新增/编辑使用右侧抽屉（移动端全屏），分三组：基本信息、登录信息、成本与提醒线。
- **只有登录信息变化时才要求重新测试读取**；结果就地显示在“登录信息”组底部（能读到就显示账户名与余额，读不到就显示原因）。
- 已归档标签页中每行有“恢复”操作（接口已支持）。
- 编辑页打开“这是我的自营站点”后，只对上游有用的“算进利润”和“渠道里用的其他地址”不显示（原来的值照旧保存，不清空）；“汇率”那一格改叫“售价”（用语见 ui-copy-spec.md §7）。“余额提醒线”“不再续费”照旧显示，自营站点的余额也会推送提醒。
- 渠道绑定抽屉：
  - “确认绑定”放在抽屉底部的吸底操作栏，挨着测试读取的结果和预览（§4.8）；不放在顶部右上角。
  - 从需处理的“有 N 个渠道还没绑定”点“去绑定”进来时，“算利润”默认勾上。
  - 预览里“不变 / 加上 / 去掉”只写有内容的那几行，三行都空时这一块不显示。
  - “这把 Key 还给别处用吗？”一开始不选（ui-copy-spec.md §5.2）。
- 登录信息说明如实描述：“登录信息保存在控制台服务端的数据库中，只用来读取这个上游的余额和用量。”（经核查，`server/` 与 `db/` 中没有任何加密逻辑，登录信息为明文存储；若后续加上静态加密，再改为“加密保存”。）

  - 还没有通知方式时整页只放一件事（下面第 5 条），不分栏。
  - 数据多的时候：规则固定 7 条；通知方式只露前 4 个，十几个时也只多一行「还有 N 个通知方式」，规则那块不会被右栏撑出大片空白。

- 页面分三个区块：**提醒规则**（规则表：开关 / 触发条件 / 通知到）、**通知方式**（一个一行：名字和开关、类型和最近测试结果、操作，见上面的版式）和**日报**。
- 规则关闭时，「发到」那一列禁用；条件里只有「连续读不到几次」禁用。余额提醒线、提醒天数也决定页面上的档位，关掉提醒也能改（ui-copy-spec §8.3）。还没有通知方式时，这两个数单独放在空状态下面那一小块。
- 全局余额提醒线放在「余额偏低」那一行，`InputNumber`，和「快用完」的天数框同样子；全页改了马上保存，标题旁写保存状态（ui-copy-spec §8.3），没有「保存规则」按钮。
- 还没有通知方式时整页只放「还没有通知方式」一块（各种通知方式的按钮 + 添加通知方式），下面加一小块余额提醒线和提醒天数；提醒规则和日报等加好以后再出现。
- 通知方式为空时列出全部 10 种可选方式并提供“添加通知方式”按钮。
- 新增“利润需处理”规则，可选通知方式。

### 5.8 系统设置 `/settings`

- 版式（#64 第 9 节，版式 PR 5）：1200 以上两栏各 6 列（`.jy-grid-2`）。左：刷新与数据、历史数据保留；右：账户安全、关于。1200 以下单栏，顺序不变。首次登录必须先改密码时只放账户安全一块，不分栏。
- 历史数据保留里，「历史概况」「最近自动清理」收进收起区「历史概况和自动清理」（§4.11），收着时露一句「共 10 条记录，最早 10月24日」；展开以后、重新读取失败时（上面已经有原因）这一句不写；上次自动清理没完成时直接展开（ui-copy-spec §8.4）。

- 分组：刷新与数据、历史数据保留、账户安全、关于。余额提醒线挪到告警中心（§5.7），「刷新与数据」下面一句链过去。
- 刷新与数据、历史数据保留改了马上保存，组标题旁写保存状态（ui-copy-spec §8.3）；账户安全照旧按「修改密码」。
- 余额提醒线（现在在告警中心）和余额用同一个币种（直接拿余额比较，与 §4.5 一致），不单独改成人民币。
- 修改密码：真正的 `<form>`，当前密码 / 新密码 / 确认新密码，`autocomplete` 分别为 `current-password` / `new-password`，按钮“修改密码”。

### 5.9 登录

- 页面有 `h1`“登录炬元控制台”。

## 7. 可访问性、深色模式、响应式检查表

- [ ] 正文对比 ≥ 4.5:1，大字与图形 ≥ 3:1，两种主题分别验证。
- [ ] 所有交互元素有可见焦点；键盘可完成全部任务；无嵌套交互元素。
- [ ] 状态永远是 图标 + 文字 + 颜色，不单靠颜色。
- [ ] 图表有图例或直接标注，并可切换为表格。
- [ ] 说明文字不放在 `title` 属性里，改用可见的说明或 `Tooltip`（可聚焦触发）。
- [ ] 主题在首帧前确定：在 `<head>` 内联脚本读取 `localStorage` 并设置 `data-theme`，避免闪白。
- [ ] 深色模式单独校验图表色板（已完成，见 §3.3）。
- [ ] 移动端点击目标 ≥ 44×44；表格转列表；抽屉全屏。
- [ ] `prefers-reduced-motion` 下关闭所有过渡。
