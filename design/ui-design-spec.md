# 炬元控制台 · UI 设计规范与改版方案

> 对应问题清单见 [ui-audit.md](./ui-audit.md)；可交互高保真稿见 [mockups/index.html](./mockups/index.html)。
> 本方案是**演进而不是重做品牌**：保留钴蓝主色、深色侧栏和品牌标记，重做的是信息组织、令牌体系和数据表达。

## 0. 这个产品在回答什么

使用者是自己经营 AI API 转售业务的运营者，一天会打开控制台很多次，其中不少是在手机上。每次打开，他想在 5 秒内知道三件事：

1. **今天赚没赚钱**——收入减去上游消耗和固定成本，还剩多少。
2. **哪个上游快没钱了**——按当前消耗速度还能撑几天。
3. **有没有必须我处理的事**——查询失败、即将到期、对账异常。

现状把这三件事分散在 4 个页面、几十张卡片里。改版的全部取舍都服务于这三个问题。

## 1. 设计原则

1. **等式即界面。**利润就是一道减法，那就把减法直接画出来：`收入 − 用量成本 − 固定成本 = 毛利`。这是本产品唯一的“招牌”元素，出现在总览、自营业务、成本与利润三页的首屏；除此之外的一切保持安静。
2. **颜色只说一件事。**状态色（正常/注意/紧急）只表示状态，并且永远配图标和文字；系列色只表示“这是哪条数据”；金额本身一律用正文墨色。“正数就是绿色”这种规则取消。
3. **平面优先，少用卡片。**层级靠三种底色和发丝线建立，而不是给每块内容套一个带阴影的卡片。只有“可以单独被操作的对象”才做成卡片（例如移动端的一个上游资源）。
4. **报数据时间，不报拉取时间。**每一组数字都标明它采集于何时（“数据截至 14:32”），而不是页面何时请求了接口。
5. **不确定就明说。**数据不完整时用 `≈` 前缀、斜纹占位和一句原因说明，不用红色吓人；未配置是引导，不是报错。

## 2. 信息架构与导航

### 2.1 导航分组

侧栏从平铺 8 项改为 3 组，组名只作为分隔，不可点击：

| 分组 | 页面 | 路由 |
|---|---|---|
| 监控 | 运营总览 · 上游资源 · 用量分析 | `/` `/stations` `/usage` |
| 经营 | 自营业务 · 成本与利润 · 渠道对账 | `/my` `/analytics` `/reconciliation` |
| 系统 | 告警中心 · 系统设置 | `/notifications` `/settings` |

- 菜单项使用 Next `<Link>`，可在新标签页打开。
- “上游渠道对账”菜单名缩短为“渠道对账”，页面标题保持全称。
- 需要处理的数量以数字徽标显示在“运营总览”菜单项右侧（仅紧急+注意，>0 时显示）。

### 2.2 应用外壳

```
┌──────────┬────────────────────────────────────────────────────────────┐
│ ▌炬元     │ 运营总览                        数据截至 14:32   ⟳   ◐   管 │  ← 顶栏 56px，sticky
│          ├────────────────────────────────────────────────────────────┤
│ 监控      │                                                            │
│ ▎运营总览 3│   页面内容（最大宽度 1440，左对齐，左右留白 24）                │
│  上游资源  │                                                            │
│  用量分析  │                                                            │
│ 经营      │                                                            │
│  …       │                                                            │
└──────────┴────────────────────────────────────────────────────────────┘
```

- **补上桌面顶栏**（修复审计 V1）：左侧为页面标题 `h1`（顶栏即页头，不再在内容区重复一个 PageContainer 标题，从根本上消除 V2 标题截断）；右侧依次为数据时间、刷新、主题切换、账户菜单。
- 刷新按钮触发**当前页面**的数据重取（通过页面注册的 `onRefresh`），而不是只刷新外壳。
- 侧栏宽 232px，可折叠到 64px；折叠状态持久化到 `localStorage`。
- 移动端（<768px）：顶栏左侧为菜单按钮 + 页面标题，品牌标记使用深色版本（修复 V3/V4）；侧栏以抽屉形式出现，首帧不渲染（修复 V5）。

### 2.3 URL 即状态

时间范围、筛选、标签页、排序全部写入查询参数（`?range=7d&tab=users`），刷新和分享链接后状态不丢；跨页跳转用 `<Link href="/stations?status=attention">` 带上上下文。

## 3. 视觉基础

### 3.1 单一令牌来源

新建 `lib/design-tokens.js`，导出 `light` / `dark` 两组令牌对象，作为唯一来源：

- `providers.tsx` 用它生成 antd `theme.token` 与 `components`；
- antd v6 默认开启 CSS 变量（`--ant-*`），自定义 CSS 直接引用 `var(--ant-color-primary)` 等；
- 产品特有的少量变量（侧栏、图表系列、状态浅底）由 `providers.tsx` 以 `style` 注入到 `<html>`，命名为 `--jy-*`；
- 删除 `globals.css:5-51` 中手写的 `--jy-*` 重复定义。

**颜色跟随度量**：金钱类图表按“这是什么钱”上色；token/请求类图表按“这是谁”上色。

| 槽位 | 含义（金钱类图表） | 浅色（底 `#FFFFFF`） | 深色（底 `#151C25`） |
|---|---|---|---|
| 1 | 收入 | `#3157D5` | `#6481EC` |
| 2 | 用量成本 / 消耗 | `#EB6834` | `#D95926` |
| 3 | 固定成本 | `#1BAF7A` | `#199E70` |
| 4 | — | `#EDA100` | `#C98500` |
| 5 | — | `#E87BA4` | `#D55181` |

| 7 | — | `#8A3FB8` | `#9085E9` |
| 8 | — | `#E34948` | `#E66767` |

校验结果（`validate_palette.js`）：

- 浅色 8 槽：相邻色觉差 ΔE 最低 9.1、常规视觉最低 19.6，全部通过；槽 3/4/5 对白底 < 3:1，按规则**必须配直接标签或表格视图**。
- 深色 8 槽：全部通过，全部 ≥ 3:1。
- 收入/用量成本/固定成本三色**两两**校验（任意组合同屏）：浅色最低 ΔE 9.2、深色 9.4，全部通过。
- 按实体上色的图表（按模型、按用户、按上游的 token 用量）最多同屏 3 个系列两两可分；超过 3 个用堆叠/相邻比较（相邻校验通过），超过 8 个合并为“其他”。

**顺序色**（热力图等）：单一钴蓝色相 `#9DB2F0 → #6F8CE6 → #3F66DA → #2A4DB8 → #1D3886`，有序校验通过，最浅一级对白底 2.09:1。

**禁用**：双轴图、甜甜圈比较相近值、用文本色当系列色、给每个数据点标数值、虚线网格。

### 3.4 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 拉丁字母与数字 | **IBM Plex Sans**（400 / 500 / 600） | 数字字形辨识度高（1 与 7、0 与 8 不易混淆），自带等宽数字特性，偏工程感，契合“账本”气质。通过 `next/font/google` 自托管，替代声明了却从未加载的 Geist。 |

**数字规则**：表格列、坐标轴、会纵向对齐的数字用 `font-variant-numeric: tabular-nums`；单独展示的大数字（等式条）用默认比例数字。

| `fs-strong` | 16 / 24 | 600 | 面板标题 |

### 3.5 间距、圆角、层级

- **间距**：4 为基数，只用 `4 · 8 · 12 · 16 · 24 · 32 · 48`。页面左右留白 24（移动端 16）；区块间距 24；面板内边距 24（移动端 16）；表单项间距 16。
- **圆角**：只用三档，按层级区分——`4` 标签/徽标/条形端点，`8` 按钮/输入框/面板，`12` 抽屉/弹窗/浮层。
- **层级**：页面内容不用阴影，只用 1px 描边；阴影只给浮起来的东西（下拉、弹窗、抽屉、提示框），统一一档 `0 8px 24px rgba(21,32,51,.12)`。

### 3.6 断点

与 antd Grid 对齐，CSS 与 JS 使用同一组数值：`sm 576 · md 768 · lg 992 · xl 1200 · xxl 1600`。删除 360 / 480 / 900 / 1199 等游离断点。

| 宽度 | 布局 |
|---|---|
| < 768 | 单列；侧栏为抽屉；表格转为列表卡片；等式条纵向排列 |
| 768–991 | 侧栏折叠为图标栏；两列网格退为单列 |
| ≥ 992 | 完整侧栏；两列网格 |
| ≥ 1440 | 内容最大宽度 1440，左对齐 |

### 3.7 动效

只保留响应操作的动效：抽屉滑入 200ms、展开行 160ms、数值更新时旧值淡出。取消骨架闪烁：**已有数据时刷新，保留旧内容并降低不透明度到 0.6，不替换成骨架**。尊重 `prefers-reduced-motion`。

## 4. 组件模式

### 4.1 时间范围选择器 `<RangePicker>`

全站统一一个组件，替代 5 种写法（审计 §4）：

- 预设：`今天 · 近 7 天 · 近 30 天 · 近 90 天 · 自定义…`。页面可声明子集（总览只用前三项；分析页全部）。
- 选中即生效，没有单独的“查询”按钮（修复对账页预设不生效的问题）；自定义范围在弹层中确认后生效。
- 控件下方或旁边始终显示解析后的实际窗口：“9月18日 00:00 至 9月24日 14:32”。
- 写入 URL `?range=7d` 或 `?from=…&to=…`。

### 4.2 利润等式条 `<ProfitEquation>`

本产品的招牌组件。

```
收入              用量成本            固定成本             毛利
¥1,248.60    −    ¥830.21       −    ¥40.00       =    ¥378.39
较昨日 +12%        6 个上游            按月摊销            毛利率 30.3%
```

- 四项水平排列，运算符 `−` `=` 用 32px 细体墨·弱色，数字用 `fs-hero`。
- 结果项“毛利”放在钴·浅底上，是整条的视觉终点。
- 每一项可点击，跳到对应明细（收入 → 自营业务，用量成本 → 上游资源，固定成本 → 上游资源固定成本筛选）。
- **数据不完整**：缺失项显示斜纹底 + “部分数据缺失”，结果前加 `≈`，结果颜色保持墨色，并在下方给出原因（如“1 个上游查询失败，消耗未计入”）。**不用红色。**
- **亏损**：结果显示为 `−¥12.40`，前缀状态图标“紧急”菱形 + 文字“亏损”；数字本身仍是墨色。
- 移动端纵向排列为账单式：每行一项，运算符在左列，结果项之上有一道 2px 横线。

### 4.3 待处理列表 `<AttentionList>`

替代总览中“余额偏低 N 个”计数和分散的动作卡片，口径统一。

- 每行：状态图标 + 对象名 + 一句话说明发生了什么 + 一个主操作 + 次操作链接。
- 排序：紧急 → 注意 → 信息，同级按预计耗尽时间。
- 空状态：“目前没有需要处理的事项。上次检查 14:32。”
- 同一对象的多个问题合并为一行，列出最严重的一个，其他收入“另有 1 项”。

### 4.4 余量跑道 `<Runway>`

用“还能撑几天”替代“余额是多少”作为上游的主指标。

- 水平条长度 = 预计可用天数（刻度 0–14 天，超过 14 天封顶并显示实际值）。
- 条上两条刻度线分别为“注意”和“紧急”阈值，**读取告警设置 `etaDays`，不写死 3/7**。
- 条颜色：正常为墨·弱色；进入注意/紧急区间才使用状态色，并在数值旁加图标和文字。
- 旁边显示余额与日均消耗；查询失败时条变为空心虚框，显示“无法计算”。

### 4.5 金额显示

| 规则 | 说明 |
|---|---|
| 颜色 | 金额一律墨色。只有“状态”才上色（通过状态标签，不给数字本身上色）。 |
| 精度 | 人民币与美元默认 2 位小数；单价、微额（< 0.01）显示到 6 位有效数字，**禁止指数表示法** |
| 币种 | 全站以人民币为主币种；美元站在金额旁小字显示原币 `$214.30`；缺失汇率时显示“未设置汇率”而不是按 1:1 静默折算 |
| 负数 | 使用真正的减号 `−` 而非连字符 |
| 近似 | 估算值前加 `≈` |
| 对齐 | 表格中金额列右对齐、等宽数字 |

### 4.6 数据状态 `<DataState>`

所有页面共用一套：

| 状态 | 表现 |
|---|---|
| 首次加载 | 与真实布局同形的骨架（面板位置、行数一致） |
| 刷新中 | 保留旧数据，面板不透明度 0.6，顶栏刷新图标旋转 |
| 空 | 一句说明 + 一个行动按钮（“添加第一个上游资源”） |
| 未配置 | 分步引导（见自营业务） |
| 局部失败 | 失败的面板内显示原因 + 重试，其余面板正常显示 |
| 整页失败 | 保留页头与筛选，在内容区显示原因 + 重试 |
| 数据过期 | 数据时间超过 2 个刷新周期时，顶栏数据时间变为“注意”色并加图标 |

补齐 `app/(dashboard)/error.tsx` 与 `loading.tsx`。

### 4.7 表格

- 金额、数量右对齐；首列（对象名）在横向滚动时固定；操作列固定在右侧。
- 主要列可排序，默认按“需要关注的程度”排序。
- 行不可整体点击（避免嵌套交互元素，修复 `role="button"` 行问题）；对象名是链接，操作是按钮。
- 行操作常驻可见，不依赖悬停。
- 移动端转为列表：每项两行，上行名称 + 状态，下行关键数字。
- 禁止表格中再嵌套可横向滚动的表格；展开内容用定义列表或无滚动的小表。

### 4.8 表单

- 所有密钥（访问令牌、API 密钥、Bot Token、Webhook、SMTP 密码）使用 `Input.Password`，`autoComplete="new-password"`；编辑时占位符显示“已保存”，下方说明“留空则继续使用已保存的令牌”；输入新值后说明改为“保存后替换原来的令牌”。
- 数字用 `InputNumber`，带单位后缀；清空时视为“未设置”而不是 0。
- 校验错误显示在字段下方，并滚动到第一个错误；toast 只用于“已保存”这类全局结果。
- 保存按钮紧跟它所保存的字段组：每个设置分组有自己的“保存”，或整页表单使用吸底操作栏并提示“有未保存的修改”。

## 6. 文案与术语

| 统一用词 | 不再使用 | 说明 |
|---|---|---|
| 上游资源 | 站点、中转站、资源（单独使用时） | 指你向其采购额度的上游；具体某一个称“上游” |
| 自营站点 | 自营资源、我的站点 | 你自己运营、向下游售卖的站点 |
| 渠道 | —— | 仅指自营站点内的渠道（channel），对账页使用 |
| 收入 | 本站收费、期内收入、销售额 | 下游付给你的钱 |
| 用量成本 | 消耗、消费、上游成本 | 按量扣除的上游费用 |
| 固定成本 | 固定付费、月费 | 按期付费的服务器、订阅等 |
| 毛利 | 利润、已确认毛利 | 收入 − 用量成本 − 固定成本 |
| 可用天数 | 跑道、预计耗尽 | 余额 ÷ 日均消耗 |
| 数据截至 | 最后刷新、更新于 | 数据采集时间 |

文案规则：动词开头、说清结果；错误说明“发生了什么 + 怎么办”，不道歉；不用“·”把多个信息硬串成一行，改为分栏或换行。
