# 决定记录

哪天定了什么、为什么，规则现在写在哪。

- 只记已经落地的决定。定了、还没做的，写在各设计稿里「已定的」那一节，做到哪见[待改总表](./pending.md)。
- 谁来加（2026-10-26 起，总指挥定）：功能 PR 不改这份文件，把要加的行和要改的「后来」写在 PR 说明的「决定记录（合并后补）」里（[CONTRIBUTING](../CONTRIBUTING.md) 第 3 节）。合并以后由设计会话攒几条，开一个只改文档的 PR 补进来，编号按合并的先后排。
- 一条一行，编号只往后加，不重排；别处说「决定记录第 N 条」就是这里的编号。
- 只写定了什么、为什么，不抄聊天原话。日期是定下来的那天，不是合并那天；日期后面写是用户定的还是总指挥定的。
- 「规则现在在哪」写现在以哪份文档的哪一节为准，括号里是让它落地的 PR（补录时照写那个功能 PR 的号，不写补录 PR 的号）；只写在代码里的，写代码的位置。
- 后来被别的决定改掉的不删，在「后来」那一列写被第几条取代；已经定了要改、还没落地的，写「以后：……」。
