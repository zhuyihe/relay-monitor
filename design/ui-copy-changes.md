# 界面用语改动记录

这份记录按页面列出，界面上的话照 `design/ui-copy-spec.md`（下称「规范」）改了哪些，给财务、运营和开发对照用。改动分三批：A1、A2、A3。这里先记 A1，A2 和 A3 在各自的 PR 里接着往下写。「原来」「现在」两列都照代码原样抄；`X`、`N` 表示会填进名称、时间或数字的地方。

## A1 · 共用的文案来源

同一句话只在一处定义，页面都从这里取（规范 §12）。

| 模块 | 管哪些话 | 哪些地方在用 |
|---|---|---|
| `lib/reconciliation-contract.js`（ISSUES，§5） | 每种问题的标题、说明、实时时的提示和按钮；渠道状态（§5.6）；「这把 Key 还给别处用吗？」和它的回答；「N 个渠道里 M 个已算进利润」 | 每日利润、渠道绑定、改绑定、上游账单；服务端的推送、每日利润和渠道绑定接口 |
| `lib/workflow-actions.js`（ACTIONS，§3.5） | 按钮名和完成提示；测试读取的结果句；「这条已经变了，刷新后再看。」；「以前的每日记录还在」 | 渠道绑定、改绑定、上游账单、上游资源页、每日利润、运营总览「需要处理」和侧栏计数 |
| `lib/error-copy.js`（§8.2） | 报错归成 13 类，每类一句话和一个下一步按钮；`failureText` / `failureSentence` 拼成「X：原因。」；`requiredText` 写漏填「请填 X」 | 渠道绑定、改绑定、上游账单、每日利润和计算明细；`lib/client.ts`；服务端每日利润 |
| `lib/format.js` | 「1 美元 = X 元」；「已删除的上游」；两句没设置汇率；「还没设置自营站点」；「没有需要处理的事。」；「计入固定成本」；「数据截至 14:30」；「刷新失败，数据截至 X。」；按哪个时区算一天；日期和日期范围 | 每日利润各块、上游账单、渠道绑定、改绑定、运营总览 |
| `lib/channel-onboarding.js`（BINDING_COPY） | 「预览」「请至少选一个渠道」「还在用这把 Key 但没绑定的渠道」「读不到自营站点的渠道」「暂停监控」「自营站点」；用途「看余额」「算利润」、两种用途各做什么的那句、「只用 Key 的上游要选「看余额」」 | 渠道绑定、改绑定、上游账单、每日利润 |
| `server/reconciliation-repository.js`（REPOSITORY_ERRORS） | 读写绑定时的 6 种报错，每种带一个码；MySQL 版和测试用的内存版抛同一个码、同一句话，界面按码归类 | 每日利润接口 |
| `app/components/error-detail.tsx` | 收起的「查看详细原因」：标题「发给技术同事看」、报错原文、「复制」 / 「已复制」 | 渠道绑定、改绑定、上游账单；每日利润的汇总、绑定列表、计算明细和以前的每日记录 |

每日利润页的按钮名（「刷新」「重新读取」「去设置」「以前的每日记录」）放在 `recon-format.ts` 的 RECON_BUTTONS，值都取自 `lib/workflow-actions.js`；「去设置」的地址也取自那里，和「需要处理」里的同一个。

页面名和标签页名在 `lib/brand.js`，有两处改动：
- 导航「账单核算」→「每日利润」，「监控估算」→「成本估算」。
- 新增标签页名表 STATION_TABS：「上游列表」「渠道绑定」「上游账单」。

- **整页读不到。**原来写「无法加载账单核算」或「无法读取核算数据」，带报错原文和「重新加载」「重新查询」。现在写「读不到每日利润：原因。」，原因按 §8.2 归类，加「刷新」，原文收进「查看详细原因」。有旧数据时写「刷新失败，数据截至 X。」，加「刷新」。
- **读不到自营站点的渠道。**原来直接把报错原文当标题。现在和渠道绑定里同一句「读不到自营站点的渠道：原因。」，原文收进「查看详细原因」。
- **首次加载。**原来写「正在读取账单核算」，现在是「汇总」和「绑定列表」两块骨架屏。
- **还没设置自营站点。**原来是「还不能开始核算」「前往上游资源」，或「本站管理员站点未配置」「前往配置」。现在统一成「还没设置自营站点」，后面跟「在上游资源里编辑你的 New API 站点，打开「这是我的自营站点」。」，按钮「去设置」。
- **没设置汇率。**原来是「金额按系统原值（美元）显示」「去设置汇率」，现在是「没设置汇率，按美元显示」「没设置汇率的：名称」「去设置」。
- **汇总下面删掉的：**
  - 「全量汇总读取失败 · 摘要仅供参考」和「重读全量汇总」；
  - 「仅已确认范围的金额，不代表全站完整利润。」；
  - 汇率、账号扣费时间和核算关联编号那一行。
- **汇总下面改写的：**
  - 币种说明改成「按各自设置的汇率换算成人民币（已固定的日子按固定时记下的汇率）。」；
  - 实时预设下加一句「今天的数字还会变，过了零点自动固定。」；
  - 有包月上游时写「包月上游的上游成本写「计入固定成本」；扣掉固定成本后的净利见自营业务。」
  - 「未计入成本的关联：rule-1、rule-2。」改成「上游成本没算进来的绑定：Key 名、Key 名。」，写 Key 名不写编号；原来只在分组小计里有，现在只有一份汇总时也写在汇总下面。
- **没算进利润的上游成本。**
  - 说明改成「上游扣费（和「自营业务」读的是同一个数）减去已算进利润的上游成本。」
  - 状态原来是「已取全」「估算」「部分」「读取中」「读取失败」。现在读全了不加标签，估算的数字前加「≈」，其余写「没读全」「读取中」「读不到」。
  - 已算进利润的多于扣费时，写「有的上游已算进利润的多于上游扣费，合计里按 0 算。」
  - 按钮「查看各上游账号」改成「查看各上游」。
- **渠道。**原来写「已知渠道覆盖：已核算 x/y」，现在写「N 个渠道里 M 个已算进利润」，按钮「查看没算进来的」。每个渠道显示状态标签、原因和按钮，不再列核算关联编号。
- **列表按钮和筛选。**
  - 行内「重试」改成「重新读取」。
  - 行内的「重新读取」和需处理按钮，读屏时都带上 Key 名，例如「更新登录信息 Key A」，手机版也一样。
  - 「去上游账单处理」删掉，页头说明改成「每天的收入、上游成本和毛利。去绑定、改绑定、解除绑定请到上游账单。」
  - 筛选只剩「全部」「需处理」「亏损」，「切换待确认 N」删掉。
- **计算明细。**
  - 只留这些行：时间、上游、Key、分组 / 倍率、收入、上游成本、毛利、毛利率、汇率、固定于、开始统计、改过。
  - 删掉的行：请求窗口、返回账单实际窗口、当前核算范围版本、首次结账、账单时区能力、风险差额等。
  - 汇率写「1 美元 = X 元，X 固定时记下」。收入和上游成本的汇率不同时，写「收入按 A，上游成本按 B」。
  - 单条重新读取没成时写「重新读取没完成，请稍后再试」。
  - 倍率时段旁的说明：「切换时间待确认」改成「倍率变化的时间是系统估的」，「已人工确认」改成「倍率变化的时间是手动改的」，「初始分段」不再写。
- **以前的每日记录。**
  - 删掉「第 N 版」「迁移的旧账」「原账单窗口」「原本站来源」「成本计法」「结账版本」等。
  - 改过的写「改过 N 次」。
  - 区块下写「每天固定后不会再变，也不算进上面的汇总。默认看最近 31 天，一次最多查 31 天。」
  - 读不到时，「历史读取失败，请重试」改成「读不到以前的每日记录：原因。」；「历史关联目录读取失败」改成「读不到绑定列表：原因。」；「重试」改成「刷新」。
- **从「需要处理」点进来的那一条。**
  - 标题写「Key 名 · 日期」。
  - 按钮「重查该窗口账单」改成「重新读取」，「原确认历史」改成「以前的每日记录」，「刷新处理目标」「返回当前账单」改成「刷新」。
  - 「去上游账单处理」和「涉及关联：…历史账单保留。」删掉。
  - 绑定已经没了时，写「这条绑定已解除」。

## A1 · 状态和问题

- **每天只剩三种状态（§4）。**
  - 原来列表状态有「正常」「待确认」「数据过期」「负毛利」，问题标签有十几种，例如「数据正常」「分组或倍率已变化」「分段切换时间待确认」「Key 不可用或无权限」「渠道来源待核对」，颜色各异。

- **实时和已固定的写法。**实时旁边写「数据截至 14:30」，过去的日子再加「还在读取」；已固定悬停写「X 固定」。

- **问题按 §5 分三类。**
  - 需处理：9 个码，共 7 句。
  - 读取类：7 个码，另加 4 个旧码。今天和过去 7 天里只当提示显示，过了 7 天还没读到才变成需处理。
  - 提示类：8 个码，不改状态。
- **旧码。**STALE、GROUP_OR_RATIO_CHANGED、BILLING_WINDOW_UNCONFIRMED、OWN_FLOW_INCOMPLETE 都写「这天的数据不完整」（§5.5）。
- **认不出的码。**写「这条暂时算不出利润」，加「刷新」；码只写进浏览器控制台（`[每日利润] 不认识的问题码：…`）。

## A2-1b · 报错归类

报错统一按码归类（§8.2）。读上游、接口、存储出错时在出错的地方给码，页面和接口都用 `lib/error-copy.js` 的 `describeError` 认是哪一类；原文只进「查看详细原因」。原文里的 401、500 这些数字不再当关键词认。

**共用的归类（`lib/error-copy.js`）**
- 服务端要交出一个码时都用 `errorCodeOf`：带着认得的码就用它；没有的按原文归到哪一类，给这一类的代表码；认不出时给调用方定的兜底码，没定就不带。读上游、接口外壳（`lib/api.js` 的 500）、`/api/usage`、自营接口、成本和流向（`server/own-helpers.js`）、对账取自营渠道、渠道绑定都用这一个。
- 「要改的绑定已经变了」（`STALE_SCOPE`）说「这条已经变了，刷新后再看」。
- 「同一把 Key 下几个渠道的选择互相冲突」（`GROUP_CONFLICT`）单独一句：「几个渠道的选择互相冲突，请改好后重新预览」，不给刷新按钮。
- 规范 §8.2 第二张表跟着改了这两行，另把「登录信息没填全」改成「地址或登录信息没填全」。

**读上游（`lib/providers.js`）**
- 读余额、测试读取这些地方用 `providerError(code, 脱敏原文)` 抛出，`queryStation` 的结果和 `balance` 带上 `code`。
- HTTP 状态：401 → 登录信息不对；403 → 没有权限；404 → 地址或类型不对；429 和 5xx → 上游繁忙；其余不给码，按原文归类。
- 请求没发出去或没回来：
  - 连不上、超时、被中止 → 连不上；
  - 地址写得解析不了 → 地址或类型不对；
  - 别的（比如令牌里混进中文字符，请求头发不出去）不给码，按原文归类。
- 缺地址或登录信息、两步验证、人机验证、数据看板没开、对方版本太旧各有自己的码。
- 登录时被拒（403）多是账号停用或人机验证没过，不按「没有权限」说，交给原文归类。
- 分组报错「账单能力验证暂时失败，可稍后重试」改成「暂时没确认上游能不能按 Key 读账单，可稍后重试」（只在「查看详细原因」里出现）。
- 删掉 `httpErrorMessage`、`reconciliationProviderError`。
- 这几处没改，照旧：
  - New API 账号那边的读取（账号身份、站点状态、Key 列表、日志统计，走 `newApiResponseError`）：401、403 或原文带「权限」算没有权限，其余都算上游繁忙；日志统计 404 也算上游繁忙。这些码进对账的状态，改了会动对账结果。
  - 只有原文、不带码的几处：Key 名称无效、自营站点读用户 / Key / 日志时对方回 `success: false`、渠道统计失败。这些按原文归类。

**测试读取（`/api/stations/test`、上游列表、上游详情）**

`lib/connection-test.js` 只留脱敏 `connectionDiagnostic`，自己那套分类删掉，改用 `describeError`。

## A2-3 · 成本估算、用量分析、自营业务

成本估算、用量分析和自营业务三页换成规范里的叫法。时间范围、Token 说明、汇率和售价、可用天数、利润等式的说法都取共用的那一份；只在一页出现的话放进该文件顶上的 `COPY`（成本估算和用量分析放在同目录的 `copy.ts`，界面测试直接引用）。报错按码说成「X：原因。」，原文只进「查看详细原因」。

**共用的来源**
- **`lib/format.js`。**
  - `formatDayKey`：接口按天给的日期（「2026-10-09」）今年写「10月9日」，往年写「2025年10月9日」。不再按时区换算，时区只用来判断「今年」；日历上没有的日子（2 月 30 日）写「—」。`formatZonedDate` 也改用它。
  - `weekdayOfDayKey`：这一天是周几，「周五」。按日历算，和浏览器时区无关，认日期的规则和 `formatDayKey` 一样。
  - `formatSinceToday`：利润等式标题旁的时间，从今天 0 点起写「0:00–14:30」，更早的写「10月14日–今天」。运营总览和自营业务共用，都写到数据自己的结束时间（刷新失败时停在上次读到的那一刻）。
  - `RANGE_TEXT` 加「近 24 小时」「近 3 天」，用量分析和余额趋势弹窗不再各写一份。

## 时区小 PR：固定成本快到期、余额趋势

A2-2、A2-4 留下的两处「按浏览器所在时区算」，改成按业务时区（§6）。

- **固定成本快到期**（运营总览、侧栏的需处理条数、上游列表的待办）：
  - `lib/overview-actions.js` 的 `fixedExpiry` 原来把开始日期按浏览器时区的 0:00 解析。改成用 `lib/profit.js` 的 `fixedCostNowOf`，和上游列表的「N 天后到期」、成本估算的摊销同一个算法。

  - 已知限制（原来就有，上游列表和摊销也一样）：到期时刻是开始日 0 点加「天数 × 24 小时」，业务时区有夏令时、中间又跨了切换日时，会差 1 小时。默认的上海没有夏令时。
- **余额趋势弹窗**（`trend-modal.tsx`）：
  - 悬停时刻、横轴刻度、「约 X 用完」都按业务时区写。弹窗的 `tz` 是必填的，运营总览和上游列表传入。
  - 时刻改用全站同一种写法 `formatZonedTime`，不补零：「03:30」写成「3:30」。原来的 `formatHhmm` 按浏览器时区写，已经没人用，删掉。
  - 横轴刻度的算法挪进 `lib/chart-math.js` 的 `timeAxisTicks`：
    - 按小时的落在业务时区里能被间隔整除的钟点上，每天的 0 点都有刻度、写日期（原来 3/6/12 小时一格时经常一个日期都没有）；
    - 按天、按周的落在每天的 0 点，从起点之后的第一个 0 点数起。
  - 新加 `lib/business-time.js` 的 `wallTimeInTz`（某日某点整）、`isDayStartInTz`（是不是 0 点）；`formatZonedRange` 判断 0 点也改用它。

## A3-1 · 通知方式发不出去时怎么说

通知方式（告警中心里的测试、日报的发送结果）发不出去时，原来照对方回的原文显示；改成按码说规范 §8.2 通知方式那张表里的一句，原文只进「查看详细原因」。这几句不套说上游的那几类：「登录信息不对或过期了」「上游暂时繁忙」说的都是上游，按钮还会跳到上游资源。

**哪种回复说哪一句**

| 什么时候 | 原来 | 现在 |
|---|---|---|
| Telegram Token 不对（401、404）、钉钉加签不对或机器人不存在、飞书地址或签名不对、企业微信地址不对、Bark 的 Device Key 找不到、Resend 的 Key 不对、Webhook / ntfy 回 401 / 403 / 404 | 对方原文，例如「Unauthorized」「错误描述:机器人发送签名不匹配;…」 | 通知方式的地址、Token 或密钥不对，请编辑后重新填 |
| 钉钉、飞书的机器人设了关键词 | 「错误描述:关键词不匹配;…」「keywords not in content」「Key Words Not Found」 | 机器人设了关键词，消息里没有：请把关键词设成「炬元」 |
| 对方回了话但没收下（Telegram 机器人被拉黑、聊天找不到，钉钉 IP 白名单、机器人已停用，Resend 发件人域名没验证，Server酱回了错误，邮件服务器一上来就拒绝或收件人被拒，内容太长） | 对方原文 | 对方没收下这条消息，请检查发件人、收件人、群或机器人的设置 |
| 限流、对方出故障（429、5xx、钉钉 410100 / 130101、飞书 11232、企业微信 45009，SMTP 4xx） | 对方原文 | 对方暂时繁忙，请稍后再试 |
| 必填的没填 | Telegram 空 Token 会照样去请求、拿回 404；Resend「缺少收件人」 | 这个通知方式没填全，请编辑后补上（不发请求） |
| 邮箱登录被拒（SMTP AUTH 535 这类） | 「AUTH 失败：535 …」 | 邮箱的用户名或密码不对，请检查后重新填 |
| 连不上、超时、地址写错 | 原文，例如「fetch failed」「SMTP 连接超时」 | 连不上这个地址，检查地址有没有填错；还不行请联系技术同事 |
| 类型认不出 | 「未知渠道类型：x」「无效的渠道类型」 | 不支持这种通知方式 |
| 通知方式已经删了 | 「未找到渠道」「未找到该渠道」 | 找不到这个通知方式 |
| 认不出原因 | 原文 | 没发出去，请把详细原因发给技术同事 [查看详细原因] |

- 哪个平台的哪种回复给哪个码，在 `lib/notify.js` 顶部的对照表；码和那一句在 `lib/error-copy.js`。`deliveryErrorCode` 定先后：没连上对方算连不上（连接被重置也是，不原样带 ECONNRESET）→ 认得的码原样用（`SMTP_TLS_REQUIRED` 这类）→ 其余「没发出去」。原来用的是读上游那套 `errorCodeOf`，会把 Telegram 的「Unauthorized」归成上游的登录信息过期。
- 推荐的关键词是「炬元」（10-23 用户定）：告警中心落款「炬元告警中心」、测试消息、日报标题「【炬元日报】」和落款「由炬元控制台生成」都带这两个字，日报不用另加落款。原来推荐「炬元告警中心」，照着设了日报会被拒收。关键词只写一处：`lib/brand.js` 的 `NOTIFY_KEYWORD`（取品牌名），测试守着日报和测试消息都带它。
- 钉钉现网的说明多是中文「错误描述:…;解决方案:…」，只看描述那段（解决方案里会顺带提到「签名」「时间戳」）。Server酱查不到公开的错误码表：回了 200 但不成功一律算「没收下」，HTTP 出错时按 HTTP 状态。
- 「没连上对方」原来读上游（`lib/providers.js` 的 `NETWORK_ERROR_CODES`）和通知方式各认一份，合成 `lib/error-copy.js` 的 `connectionFailed`，两边都用。读上游的结果不变（原来就把「fetch failed」整个算连不上）。
- 「查看详细原因」里，fetch 原来只有一句「fetch failed」；现在后面补上底层原因，例如「fetch failed（connect ECONNREFUSED 127.0.0.1:443）」「fetch failed（UNABLE_TO_VERIFY_LEAF_SIGNATURE：unable to verify the first certificate）」，同样打码（`errorDetail`）。读上游的详细原因还是原样，没跟着改。
- 接口：`/api/notifications/test` 的结果一定带 `code`（原文照旧在 `error` 里，打过码），类型认不出时照常回 200；找不到通知方式、没说测哪个时 400 带码。新增、编辑通知方式时类型不对、已经删了，带 `NOTIFY_TYPE_UNSUPPORTED`、`NOTIFY_NOT_FOUND`。状态码都不变。

**日报的预览和立即发送**

| 什么时候 | 原来 | 现在 |
|---|---|---|
| 还没设置自营站点 | 预览：弹一条「读不到日报预览：操作没完成，请稍后再试。」；立即发送：「日报没发出去：操作没完成，请稍后再试」 | 日报区块里直接写 §8.1 那句「还没设置自营站点：……」，带「去设置」 |

**太长时**（§10）

- 原来所有聊天软件一律按 1500 个字截，末尾加「…」。企业微信一条最多 2048 字节，1500 个汉字约 4500 字节，日报发企业微信多半一直被拒。
- 现在按各家的上限截：企业微信 2048 字节（连标题一起算），Bark 3000 字节（走苹果推送，整条约 4KB，留了余量，连标题），ntfy 4000 字节（上限 4096，留了余量），其余照旧 1500 字；邮件 20000 字。截了就在末尾写「……（太长没发完，完整内容请看邮件或控制台）」（`TRUNCATED_NOTE`）。按字截，不会切开一个字。

**其他**
- 类型名是 `constructor`、`toString` 这类原型链上的名字时，原来测试会显示「测试消息已发送」（其实什么都没发）；现在说「不支持这种通知方式」。
- 「未命名通知方式」只写一处：`lib/alert-rules.js` 的 `UNNAMED_CHANNEL`（A3-2 把提醒规则表也收到这个文件）。告警中心页、`db/store.js` 都用它（原来存库时写「未命名渠道」）；编辑时把名字清空也存成这一句。
- 日报区块的结果框里，「查看详细原因」「去设置」放在文字那一列（原来会挤进图标那一列）。
- 守护加上 `lib/smtp.js`、`lib/alert-rules.js`、`app/api/notifications/**`、`app/api/report/**`；`deliveryError` 和 `new Error` 一样不扫（原文只进「查看详细原因」）。`lib/notify.js` 在 A3-2 删掉发送前的改字后再加进来。
