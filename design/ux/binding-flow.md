## 一句话说清

**你只需要知道三样东西：**

- **你的站**（自营站点）：里面有很多渠道。
- **上游**：一个上游网站上的一个账号。下面有好几把 Key，每把 Key 在上游的一个分组里；分组不同，价钱的倍率不同（倍率 1.2 就是按标价的 1.2 倍收钱）。
- **渠道和 Key**：你站里的每个渠道都填着上游的一把 Key。所以一个上游对应你站里好几个渠道；换了 Key，渠道还是那个渠道。

**利润 = 渠道每天的收入 − 这个渠道当天用的 Key 在上游花的钱。**

- 渠道的收入：你站里的用户当天在这个渠道上消费的钱，读自营站点的用量记录。
- 上游花的钱：读上游的账单（每条用量记录上游已经按当时的分组、倍率算好了钱），不是控制台自己按倍率估。
- 两边都换成人民币再相减，用的是自营站点和每个上游各自「更多设置」里的汇率，和现在一样。没设汇率时页面上写「没设置汇率」，那一处有「去设置」；不在下面的 8 下里。

每一天的利润只会是三种状态之一（ui-copy-spec §4）：**实时**（今天，数还会变；或者过去几天的账单系统还在自动重读，最多 7 天，写「还在读取」）、**已固定**（过去的日子，账单读全了，数定下来了）、**需处理**（不处理就算不准，利润写「—」，不算进汇总）。

**你只做三步：**

1. **设置自营站点**：填地址和超级管理员的访问令牌，只做一次。
2. **加上游**：填地址和令牌，回答一次「这个上游账号只给你自己的渠道用吗？」。
3. **开始算利润**：系统列出对上的渠道，你点「开始算利润」。

以后换 Key 不用管，系统自己跟上。上游账号只给你自己的渠道用时，只有两种情况会找你，每次只给一个按钮：认不出某个渠道用的是哪把 Key（「指定 Key」）；上游的登录过期了（「更新登录信息」）。账号别处也在用、或者你答了「不确定」，多一种「去回答」（附录 2）。

下面说的「三步」是三件事；每件事里要填、要点的加起来一共 8 下（第 6 节）。

第 7、8 节和写着「K 的认N」「§N」的地方是给开发、写规范的人看的，只看流程可以跳过。

## 0. 这份设计的六项（ui-design-spec §1.3）

| 项 | 写什么 |
|---|---|
| 用户目标 | 从零开始，最快看到「我的每个渠道每天赚了多少」；以后 Key 换了也不用管 |
| 流程 | 三件事、一共 8 下，中途不换页，做完落到每日利润看结果（第 1 节）。现在要约 38 步、7 次换页，还要在「测试读取」抽屉里选 Key、填时区（第 6 节） |
| 省掉了什么 | 选上游类型、选用途（看余额 / 算利润）、选 Key、按 Key 分组、填时区、「测试读取」「确认上游账号」、每把 Key 问一次「这把 Key 还给别处用吗？」、换 Key 后再绑一遍、在两个页签之间找同一件事 |

| 对照原则 | §1.2 第 1 条（类型、账号、Key、分组、倍率、时区系统自己认）、第 2 条（只有确认和更正）、第 3 条（只问系统不可能知道的那一件：账号是不是只给你用）、第 4 条（一条路从头走到尾，做完落到每日利润）、第 6 条（换 Key 不打扰） |

## 1. 主流程：从零到看到利润

每一步三栏：你看到什么、你点什么、系统在后面做了什么。系统做的事你看不到，也不用点。

### 第 1 步：设置自营站点（样稿 flow-own）

| 你看到什么 | 你点什么 | 系统在后面做了什么 |
|---|---|---|
| 一个抽屉，两栏：「站点地址」「超级管理员的访问令牌」；令牌下面一句写去哪里拿（在你站的后台用超级管理员登录，「个人设置」里生成） | 填这两栏 | —— |
| 填完、离开输入框，下面一句「能读到：站点「我的站」，120 个用户，6 个渠道」 | —— | 读你的站：站点名、用户、每个渠道和渠道里填的上游地址 |
| 底部「保存」 | 「保存」 | 记下来。以后每天读每个渠道的收入 |

读不到时，那一句换成原因（ui-copy-spec §8.2），「保存」灰着。

### 第 2 步：加上游（样稿 flow-upstream）

| 你看到什么 | 你点什么 | 系统在后面做了什么 |
|---|---|---|
| 一个抽屉，两栏：「站点地址」「令牌」；令牌下面一句写去上游后台哪里拿（ui-copy-spec §3.7 那几句，按认出的类型换） | 填这两栏 | 填地址时认出是哪种上游（New API 或 Sub2API），令牌那一栏的名字和说明跟着变（「访问令牌」或「登录令牌」）；填的是 `sk-` 开头的 Key 时，认出这是只填了一把 Key 的上游（附录 1） |
| 填完、离开输入框，下面一句「能读到：账号 演示·主力账号，余额 $158.78，3 把 Key」 | —— | 读这个账号：账号名、余额、Key 列表（每把 Key 的名字、分组、倍率）；试读一次账单，确认每天的账单能读全；定好按哪个时区算一天 |
| 一个问题「这个上游账号只给你自己的渠道用吗？」，三个选项一个都不预先选 | 选一个 | 记在这个上游上 |
| 底部「加上游」 | 「加上游」 | 记下来。接着在你的站里找连到这个上游的渠道（第 3 步） |

- 选「只给我的渠道用」：以后换 Key 系统自己跟上。
- 选「别处也在用」或「不确定」：见附录 2。
- 还没设置自营站点时，加完就停在这里，提示「已加上游」。以后设好自营站点、点「保存」时，设置自营站点的那个抽屉接着出第 3 步，已加的上游一个一组列出来。

### 第 3 步：开始算利润（样稿 flow-start）

加完上游，同一个抽屉直接换成这一步，不关、不跳页。

| 你看到什么 | 你点什么 | 系统在后面做了什么 |
|---|---|---|
| 标题「开始算利润」，下面列出你的站里连到这个上游的渠道，一个渠道一行：渠道名「高速 A」，下面一句「用的 Key：oai · 分组 a · 倍率 1.2」，默认都勾上 | 想不算的可以取消勾 | 按渠道里填的地址，认出哪些渠道连的是这个上游；按请求记录（或用量）认出每个渠道现在用的是哪把 Key |
| 有的渠道还没认出 Key，那一行写「还没认出用的是哪把 Key，先开始算，系统接着认」，照样勾着 | —— | 接着认（第 2 节例外一） |
| 底部「开始算利润（4 个渠道）」 | 「开始算利润」 | 从点的这一刻起，每天按「渠道收入 − 这个渠道当天用的 Key 在上游花的钱」算；点之前的日子不补算（和现在一样，今天写「从 14:30 开始统计」） |
| 抽屉关上，落到「每日利润」的今天，这 4 个渠道高亮一下，今天的数已经在（实时）；还没认出 Key 的那个渠道也在里面，写「实时 · 还在读取」，它的收入和成本先不算进今天的汇总（不会虚高） | —— | 之后每天自己算；过了零点、账单读全，那天标「已固定」（ui-copy-spec §4 的规则，不变） |

- 一个渠道都没找到时写「你的站里没有渠道连到这个上游」，下面一句「渠道里填的 Key 换成这个上游的以后，系统会自己找到」。
- 你在这一步取消勾的渠道，以后也不算，除非你在「渠道」页签里点它的「开始算利润」。
- 以后你在站里**新加**的渠道、填了这个上游的 Key：推荐系统找到后自己开始算，「渠道」页签上这个渠道写「10月26日起系统自动开始算」，不来找你（还没定，第 9 节第 5 条）。只对答过「只给我的渠道用」的上游这样做。
- 两个渠道填了同一把 Key：这把 Key 的上游成本只算一次，两个渠道合起来算利润，在每日利润里并成一行「高速 A、高速 B（同一把 Key）」（和现在一把 Key 绑几个渠道一样）。
- 「停止算利润」：从点的那一刻起不再算；已经算出来的日子留着，以后可以再点「开始算利润」接着算。

## 2. 只在两种情况找你（上游账号只给你自己的渠道用时）

每次只给一个按钮，点了就在原地做完。

### 例外一：认不出某个渠道用的是哪把 Key（样稿 flow-assign）

| 你看到什么 | 你点什么 | 系统在后面做了什么 |
|---|---|---|
| 今天：这个渠道写「实时 · 还在读取」，不打扰你 | —— | 接着认 |
| 那一天过完（过了零点）还认不出（认 Key 不像读账单那样重读几次就会好，所以不等 7 天）：需处理里一条「没认出这个渠道用的是哪把 Key」，说明「这段时间的上游成本先不算；指定以后就能算」，按钮「指定 Key」。每日利润里这个渠道那几天是「需处理」，利润写「—」，收入和成本都不算进汇总（不会因为少算成本而虚高，ui-copy-spec §4） | 「指定 Key」 | —— |
| 一个小窗：上面是这个上游的 Key（系统觉得像的排最前），下面是「从什么时候起」，默认「从没认出的时候起」 | 选一把 Key，点「指定 Key」 | 从那个时刻起按这把 Key 算；那几天重算 |
| 需处理那条消失；每日利润那几天有了利润，按 ui-copy-spec §4 照常变成实时或已固定 | —— | —— |

- 后来系统自己认出来了，需处理那条自己消失，不提示。
- 没有用量的渠道（新渠道还没有请求、停着的渠道）不用认，也不来找你，只在原处写「还没有请求，有了以后系统接着认」。

### 例外二：上游的登录过期了

| 你看到什么 | 你点什么 | 系统在后面做了什么 |
|---|---|---|
| 需处理里一条「登录信息不对或过期了」，说明「更新之后才能接着读取余额和账单」，按钮「更新登录信息」 | 「更新登录信息」 | —— |
| 一个小窗，只有「令牌」一栏 | 填新令牌，点「更新登录信息」 | 用新令牌读一次，读到就接着读余额和账单；过期这几天的账单补读回来（读不到的那几天原来是「实时 · 还在读取」，超过 7 天是「需处理」；补读后照常定下来，变成已固定） |
| 需处理那条消失 | —— | —— |

自营站点的登录过期也一样，小窗里填的是超级管理员的访问令牌。

## 3. 换 Key、换倍率时

**系统认得出新 Key 时，你不用做任何事**（账号只给你自己的渠道用时；认不出就是例外一。账号别处也在用见附录 2；只填了一把 Key 的上游见附录 1，那种上游换 Key 要你自己改）。

| 发生了什么 | 系统做了什么 | 你在哪里看得到 |
|---|---|---|
| 渠道里的 Key 换成了同一个上游的另一把 | 认出换了，从换的那一刻起读新 Key 的账单 | 「渠道」页签这个渠道下面的「用过的 Key」多一行「10月24日 14:30 起　oai-2 · 分组 a · 倍率 1.2」；每日利润那天写「今天 14:30 换了 Key」，那天的状态（实时 / 已固定）不因为换 Key 而变；那天的计算明细里上游成本按两把 Key 分开写 |
| 同一把 Key 换了分组或倍率 | 从变的那一刻起分成两段记（上游账单里的钱已经是按新倍率算的） | 「用过的 Key」多一行；计算明细写「倍率在 14:30 从 1.0 变成 1.2，分两段算」 |
| 认出来了，但你觉得不对 | —— | 那一行右边有「不对？指定 Key」（例外一的同一个小窗）；换的时刻不准（例如你记得是 15:00 换的），点那一行的「改时间」（同一个小窗，只改「从什么时候起」） |

- 不弹提示、不推送、不进需处理。
- 渠道里的 Key 换成了另一个上游的：这个渠道在旧上游下停算；新上游答过「只给我的渠道用」时，在新上游下接着算；新上游答的是别的，照附录 2；新上游还没加，见附录 4。

## 4. 落在哪几个页面

| 页面 | 放什么 |
|---|---|
| 运营总览「开始使用」 | 三步清单，一步一行，按钮打开对应的抽屉（[第一次使用](./first-run.md)第 2 节） |
| 上游资源 · 上游列表 | 每个上游的余额、可用天数；「加上游」打开第 2 步的抽屉 |
| 上游资源 · **渠道**（新，由原来的「渠道绑定」「上游账单」合成） | 上游 → 渠道 → 用过的 Key 三层：左 4 列是上游列表，点一个，右 8 列是它下面的渠道，每个渠道下面是「用过的 Key」；在算的渠道右上角是「停止算利润」，你取消了勾、没在算的渠道是「开始算利润」（样稿 flow-channels） |
| 自营业务 | 页顶「自营站点设置」打开第 1 步的抽屉 |
| 每日利润 | 每个渠道每天的利润；计算明细里看那天用的是哪把 Key |
| 需处理（运营总览、侧栏） | 这条流程只进两种：「没认出这个渠道用的是哪把 Key」[指定 Key]、「登录信息不对或过期了」[更新登录信息]；账号别处也在用或答了「不确定」时多一种 [去回答]（附录 2）。附录 1、4、5、6 的情况只在原处写一句，不进需处理 |

数据多的时候：
- 上百个渠道时，「渠道」页签按上游分开，一次只看一个上游的渠道；左边上游列表有需处理的排在前面。
- 第 3 步列出的渠道多时，按「认出了 / 还没认出」两组，默认都勾上，顶上一个「全选」；不分页（一个上游下的渠道一般不过几十个）。
- 「用过的 Key」先露 3 段，多的收进「再看 N 段」（收起区 `More`）。

## 5. 去掉什么

### 5.1 去掉的东西

| 去掉 | 为什么 | 以后怎么办 |
|---|---|---|
| 「测试读取」按钮（加上游、开始算利润、上游账单里） | 系统填完令牌就自己读，读到的结果直接写出来 | 填完离开输入框自动读 |

| 「选一把 Key」「测试读取选中的 Key」 | 系统自己试读账单 | 加上游时系统试读一次 |
| 时区输入框 | 系统自己定按哪个时区算一天（第 7 节） | —— |
| 选上游类型（New API / 只用 Key / Sub2API / 邮箱密码） | 系统按地址认 | 只在 Sub2API 要用邮箱密码时，令牌下面给一个「用邮箱和密码登录」 |
| 选用途「看余额」「算利润」 | 加了上游就看余额；渠道连到它就能算利润 | —— |
| 渠道绑定抽屉里「选渠道 → 选上游 → 选 Key」 | 系统按地址和请求记录认 | 第 3 步列好，你只点「开始算利润」 |

| 「渠道绑定」「上游账单」两个页签 | 说的是同一件事，分在两处要来回找 | 合成「渠道」一个页签 |

### 5.2 页面上不再出现的词

| 不再出现 | 以后说 |
|---|---|
| 测试读取（在这条流程里） | 不说，系统自己读；结果写「能读到：……」 |
| 确认上游账号、上游账号身份 | 不说 |
| 按 Key 绑、按渠道绑、绑法 | 不说 |
| 绑定、去绑定、确认绑定、解除绑定（用户看到的地方） | 「开始算利润」「停止算利润」；说一个在算的渠道就说「渠道」 |

| 渠道绑定、上游账单（页签名） | 「渠道」 |
| 找渠道 | 不说，系统自己找 |
| 时区（在这条流程里） | 不说 |
| 只用 Key 的上游 | 附录 1 的情况写「这个上游只填了一把 Key」 |

## 8. 规范要改的（ui-copy-spec，进规范以后这节作废）

- **§3.1 东西叫什么**：
  - 「上游」改成：一个上游网站上的一个账号（地址 + 令牌）；下面有好几把 Key。「上游账号」只在问题「这个上游账号只给你自己的渠道用吗？」和同一个网站有两个账号时用。
  - 「绑定」改成开发用词，界面上不出现；用户看到的是「这个渠道在算利润 / 没算利润」。
  - 「看余额 / 算利润」（作为渠道绑定的两个选项）删掉。
  - 加「用过的 Key」：一个渠道在不同时间用过的 Key，连同分组和倍率，一段一行（K 的认1）。
- **§3.5 动作叫什么**：加「开始算利润」「停止算利润」「指定 Key」（K 的认4、认10）；「测试读取」只留在编辑上游里（换了令牌时读一次），加上游、开始算利润、更新登录信息里都是离开输入框自动读。
- **§11 页签名**：上游资源的页签改成「上游列表 / 渠道」，「渠道绑定」「上游账单」不再用。
- **§5.2 需处理**：「有 3 个渠道还没绑定」删掉（第 9 节第 5 条定成系统自己开始算时；定成另一种，就改成「有 3 个渠道还没算利润」[开始算利润]）；「还没确认这把 Key 属于哪个上游账号」「还没确认能读到这个上游的完整账单」「还没确认这个上游按哪个时区算一天」三条删掉（系统自己做，做不到的照附录写成一句话，不进需处理）；加「没认出这个渠道用的是哪把 Key」[指定 Key]（K 的认2）。
- K 设计稿第 10 节的认1–认11，凡是和这里冲突的（例如认10 的「找渠道」），以这里为准。

## 9. 要你定

由总指挥去问。每条后面是推荐。

1. **合成以后的页签叫「渠道」。**
   - 推荐：「渠道」。三样东西里就有它，页签里看的就是每个渠道在不在算、用的哪把 Key。
   - 另一种：「渠道和 Key」，更直白但长。
2. **「绑定」这个词在界面上不再出现**，用户看到的是「这个渠道在算利润 / 没算利润」，按钮是「开始算利润」「停止算利润」。
   - 推荐：去掉。用户的三样东西里没有「绑定」，它是系统内部的事。
   - 另一种：保留「绑定」，只去掉「按 Key 绑」「按渠道绑」。
3. **「上游」就是一个账号**（地址 + 令牌）。现在一个账号的几把 Key 可以分开加成几个「上游」，以后加上游就是加一个账号，Key 由系统读出来。
   - 推荐：这样。已有的数据（一个账号分开加了几个上游）由开发迁成一个上游；读不出是不是同一个账号的（例如只填了 Key），照旧各是一个上游，按附录 1 显示。
4. 第 7 节标「待核对」的两件（认上游类型、Sub2API 的时区）由开发确认后，如果做不到，是在附录里多问一句，还是这类上游先不支持算利润。
   - 推荐：多问一句，只对做不到的那类上游问。

5. **以后新连上来的渠道，系统自己开始算。**上游答过「只给我的渠道用」的，你站里新加的渠道一连到它，系统就开始算，不进需处理，只在「渠道」页签上写「10月26日起系统自动开始算」。
   - 推荐：自己开始算。第 2 步你已经确认过「这个上游只给我的渠道用」，新渠道是同一件事；再来问一遍，就不是「以后不用管」了。不想算的渠道，在「渠道」页签里点「停止算利润」。
   - 另一种：新渠道照旧进需处理「有 1 个渠道还没算利润」，你点「开始算利润」才算。

## 附录：边角情况（不在正文里）

1. **只填了一把 Key、没有登录信息的上游**：系统只能读这把 Key 的余额和它自己的用量，读不到账号和别的 Key。渠道照样按地址对上；用的就是这把 Key，不用认。换了 Key 要在上游列表里改这个上游的 Key（「编辑」），不会自己跟上。页面上写「这个上游只填了一把 Key，换 Key 时要来这里改」。忘了改时：系统看到渠道还有收入、这把 Key 却没有用量了，那一天过完进例外一「没认出这个渠道用的是哪把 Key」，小窗里填新的 Key（这种上游没有 Key 列表可选），那几天重算，不会悄悄算错。
2. **账号不是只给你自己用**（答了「别处也在用」）：这个账号的钱也花在别处，系统没法确定哪把 Key 只给你的渠道用，不能自己跟着换 Key。第 3 步里每个渠道用的 Key 照样认出来，但每把 Key 多问一句「这把 Key 还给别处用吗？」，五个选项照现在的（ui-copy-spec §5.2）：「只给这些渠道用」「自营站点的其他渠道也在用」「站外也在用（测试、自用、给别人）」「别处也在用，说不清是哪」「不确定」。只有答「只给这些渠道用」的 Key 能直接算利润；自营站点的其他渠道也在用的，把那些渠道也开始算就行；站外也在用、说不清、不确定的，成本分不开，利润先不算，给渠道换一把单独的 Key 就能算；换 Key 以后，这个渠道进需处理「没认出这个渠道用的是哪把 Key」，要你「指定 Key」。第 3 步可以先点「开始算利润」再回答：没回答的那几把 Key 下的渠道先不算，需处理里各留一条 [去回答]。账号的问题答「不确定」：第 3 步照样能点「开始算利润」，但这个上游下的利润先不算，需处理里留一条「这个上游账号只给你自己的渠道用吗？」[去回答]。
3. **同一个上游网站有两个账号**：渠道地址分不出是哪个账号。上游和你的站都是 New API 而且版本够（第 7 节第 ① 档），系统按请求号分得清；分不清的渠道列在第 3 步「还没认出」那几行，过了一天还分不清就进例外一。第 3 步顶上加一句「这个网站上还有别的账号，有的渠道分不清是哪个账号的」。
4. **渠道地址对不上任何上游**：这个渠道连的上游还没加，或者渠道里填的是内网、代理地址。这样的渠道列在「渠道」页签最下面一组「没对上上游的渠道」（ui-copy-spec §3.1 已有的说法），每行一句「这个渠道连的上游还没加」[加上游]，不进需处理；加好以后照第 3 步。是内网、代理地址的，在那个上游的「更多设置」里填「渠道里用的其他地址」。
5. **上游读不到每天的账单**（版本太旧，或者账号没有权限）：加上游时写「这个上游读不到每天的账单，只能看余额」。第 3 步照样列出连到它的渠道，但不能开始算利润，那几行写同一句。
6. **你的站不是 New API**：自营站点只支持 New API，第 1 步读的时候写「自营站点要是 New API 站点」。
7. **系统定不了按哪个时区算一天**（只可能是 Sub2API，第 7 节待核对；开发确认做得到，这条就删掉）：加上游时，账号问题下面多一问「这个上游按哪里的 0 点算一天？」，默认选控制台的业务时区（部署时设定，所有页面按它算一天）。正文里不出现。
