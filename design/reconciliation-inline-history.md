# 对账页：行内分组历史与渠道目录

## 信息结构

桌面保持高密度规则总表。主行展示状态、上游账号与 Key、当前上游分组和倍率、销售渠道名称与 ID、本站收费、上游成本、确认利润、实际毛利率和最近成功时间。金额仍按顶部查询窗口计算。真实存在分组或已知倍率变更的规则，在当前分组旁显示“变更历史 · N 段”，行首有展开箭头；其余规则不出现箭头。

展开区域与主行对齐，使用浅一层的表面色和细分隔线，不叠加新卡片或阴影。历史段按最近在前排序，列为：生效区间、上游分组/倍率、本站收费、上游成本、确认利润或风险差额、实际毛利率、切换时间依据。金额右对齐并使用等宽数字。上方固定说明“金额仅对应当前查询窗口；窗口外仅保留分组与倍率记录”。窗口外金额用“—”，窗口内取数失败也用“—”；只有接口明确返回零才用 `$0.00`。未确认差额以“风险差额”标明，不进入确认利润。

## 交互与状态

- 默认全部收起。点击箭头、当前分组单元格或键盘 Enter/Space 展开；再次操作收起。桌面一次只展开一条，翻页或筛选后不保留隐藏行的展开状态。
- 行尾直接显示“详情”按钮，旁边菜单提供“编辑规则”“停止并释放”；点击这些操作不展开历史。详情用于原始账单、异常诊断与修正切换时间，不再重复整段历史列表。
- 自动检测时间未确认的历史行标记“待确认”；人工修正后标记“已确认”。倍率缺失显示“倍率未知”，不能以当前倍率补造历史。
- 手机保留独立列表。有真实历史时在卡片下方显示 44px 触控目标“查看 N 段历史”，展开后用纵向分段记录展示同一字段；不把桌面宽表压缩进手机视口。详情仍是独立操作。
- 多渠道共用一个上游 Key 时，展开区属于该 Key 的对账规则，金额是规则级合计；渠道名称和 ID 可见，但不显示未经归属的渠道成本或渠道毛利。

## 对账口径边界

当前上游倍率与历史倍率是定价上下文，不参与重新乘算账单。不同客户销售倍率可能不同，本轮不显示统一“目标毛利率”。实际毛利率始终是 `(本站实收 - 上游实扣) / 本站实收`；本站实收确认为零时显示“—”。历史行的金额仅来自它与顶部查询窗口交集的结算结果，跨窗口不能伪装成全生命周期累计。

## 渠道目录与异常反馈

添加/编辑规则打开时刷新本站渠道，搜索名称或渠道 ID。已占用选项明确标明所属规则；读取失败显示稳定的用户提示并提供重试，不显示上游原文。新请求优先于旧请求；失败时不让过期响应覆盖目录。旧版不带 total 的目录读到空页；重复页和安全上限报错，不展示部分目录供保存。
