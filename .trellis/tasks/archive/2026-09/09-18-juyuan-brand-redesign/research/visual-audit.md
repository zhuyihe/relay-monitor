# 品牌与视觉审查记录

## 审查结论

独立视觉总监给出的结论为“有条件通过”：方向正确，但原方案仍偏换肤清单，需要补成明确的品牌系统、信息层级和跨触点规范后再实施。

## 已确认问题

- `app/providers.tsx` 仅配置 Ant Design 默认蓝和圆角，没有产品级主题令牌。
- `app/(dashboard)/layout.tsx` 直接呈现 ProLayout 默认结构、通用折线图标和旧产品名。
- `app/(dashboard)/page.tsx` 使用等权 KPI 与通用 ProCard 组合，决定了平台的模板感。
- `app/login/page.tsx` 是居中默认 Card，并暴露 `admin123` 密码提示。
- `app/(dashboard)/settings/page.tsx` 在主界面宣传 Ant Design Pro、MySQL 和连接器技术栈。
- 页面与图表混用 `#1677ff`、`#0A84FF`、`#ff4d4f`、`#faad14`、`#52c41a`。
- 移动端存在 10–11px 辅助文字，需要提高到至少 12px。
- `public/manifest.webmanifest`、`public/icons/*`、`public/sw.js` 仍保留旧品牌。
- `server/report.js`、`lib/notify.js`、通知测试 API 和运行日志仍暴露 `relay-monitor` 或旧中文名称。
- 项目缺少专属 404、全局错误页和统一的加载/空状态语言。

## 已确认设计决策

- 保留“炬元控制台”，不再造英文产品名。
- “上游节点”改为“上游资源”，“用量洞察”改为“用量分析”，“财务分析”改为“成本与利润”。
- 保留 Ant Design，不迁移框架。
- 主视觉为深墨侧栏、冷灰工作区、钴蓝交互色和高密度经营数据排版。
- New API / Sub2API 在导航和总览降级，但在连接配置与排错界面保留。
- 首发必须同时覆盖深浅主题、移动端、PWA、通知、日报和全局状态，不能只换主界面。

## 风险

1. 当前移动端任务与品牌任务重叠修改布局、登录、多个页面和 `globals.css`，必须先形成独立提交。
2. 如果直接全仓替换颜色，会破坏图表比较色和状态语义，必须按语义令牌逐处迁移。
3. 如果重写 ProLayout 或引入新 UI 框架，会扩大回归面；首发应保留现有行为，只定制外观与信息层级。
4. 如果把连接器技术名全部隐藏，会损害配置和排错准确性。
5. 如果 package、Docker 镜像和内部缓存键同时改名，会把品牌任务扩大成部署迁移；首发只处理用户触点。
