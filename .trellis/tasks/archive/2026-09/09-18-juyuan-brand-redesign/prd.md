# 炬元控制台品牌化改造 PRD

## 背景

当前产品功能已经覆盖上游余额监控、下游用量、成本利润与告警，但界面仍大量暴露
`relay-monitor`、`中转站余额监控`、New API / Sub2API、Ant Design Pro 默认组件形态和默认配色。
用户希望将其改造成自有平台，而不是保留开源后台的视觉和文案气质。

本任务只改品牌表达、信息层级和界面呈现，不改变现有业务计算、数据结构和连接器行为。

## 实施前置条件

- 当前 `09-18-mobile-responsive` 任务必须先完成验收并单独提交。
- 本任务实施时以移动端任务提交后的代码为基线，不能把两项工作混入同一提交。
- “炬元”名称、域名和商标可用性由产品方确认；本任务默认已获准使用。

## 产品定义

- 品牌主名：**炬元**
- 产品名：**炬元控制台**
- 产品定位：**AI API 运营与成本管理平台**
- 登录页副标题：**上游资源、下游用量、成本与告警，一处看清。**
- 浏览器标题格式：**{当前页面} · 炬元**
- 通知签名：**炬元告警中心**
- 日报签名：**由炬元控制台生成**

| 中转站 | 上游资源 | `/stations` |

首发只修改用户可见名称，不迁移现有 URL，避免破坏书签、PWA 入口和内部链接。

## 设计原则

1. 视觉关键词是“冷静、精确、可信的经营仪表盘”。
2. 保留 Ant Design 和 Pro Components 作为底层能力，不迁移框架；禁止继续直接呈现默认 ProLayout / ProCard 示例风格。
3. 信息层级优先于装饰。品牌化不能退化为换 logo、换蓝色、加阴影。
4. 桌面保持 B2B 数据密度，移动端采用专用信息卡和抽屉导航，不压缩桌面布局。
5. 技术适配器名称只在连接配置、凭证说明和排错场景出现，不占据页面主叙事。
6. 保留原项目许可证和必要版权声明，但将其放在源码、文档或法律信息中，不放在日常工作界面。

## 品牌视觉规范

### 标识

- 标识概念：由“炬”字火部抽象为三个数据节点，汇入一条竖向主干，表达多路资源汇聚到统一经营视图。
- 禁止使用普通 JY 字母拼接、折线图、火焰轮廓、蓝紫渐变方块。
- 使用单色 SVG，必须在 16px favicon 下仍可辨认“三节点＋主干”。
- 侧栏展示图形标识＋“炬元”，弱层级副标为“运营控制台”。

### 字体与数字

- 中文正文采用系统中文无衬线回退栈。
- 拉丁字符和数字使用项目内稳定打包的 Geist Sans；不依赖运行时远程字体。
- 经营数字统一启用 `font-variant-numeric: tabular-nums`，不对整段正文使用等宽字体。
- 桌面页标题 24/30，移动端 20/28；区块标题 16/24；正文 14/22；辅助文字最低 12/18。

### 颜色

浅色：

- 页面背景 `#F4F6F8`
- 主表面 `#FFFFFF`
- 主文字 `#152033`
- 次文字 `#667085`
- 分隔线 `#DFE4EA`
- 品牌蓝 `#3157D5`
- 品牌浅底 `#EDF2FF`
- 成功 `#137A63`
- 警告 `#A86400`
- 危险 `#C83C3C`

深色：

- 页面背景 `#0F141B`
- 主表面 `#151C25`
- 分隔线 `#283343`
- 主文字 `#EEF2F7`
- 品牌蓝 `#7F9CFF`

所有页面、图表、PWA 元数据和状态颜色必须由统一语义令牌驱动，清除散落的
`#1677ff`、`#0A84FF`、`#ff4d4f`、`#faad14`、`#52c41a` 等硬编码。

## 首发范围

### 1. 品牌基础与主题令牌

- 建立可被前后端共同引用的品牌常量，覆盖名称、描述、通知签名和页面标题。
- 创建品牌标识组件和 SVG / favicon / PWA 图标资产。
- 完成 Ant Design 浅色、深色主题令牌及必要组件级覆盖。
- 建立全局排版、数字、焦点环、间距、圆角、阴影和层级规范。
- 更新 metadata、viewport、manifest、theme color 和 service worker 缓存命名。

### 2. 应用外壳与登录页

- 深墨色桌面侧栏宽 232–240px，品牌区、菜单间距、选中态全部定制。
- 顶栏只承载当前页面上下文与全局动作；主题切换进入用户菜单或系统设置。
- 移动端使用品牌顶栏和抽屉导航，保留至少 44px 触控目标。
- 删除全局页脚中的版本和 commit；移至“系统设置 → 系统信息”。
- 登录页桌面采用约 42% 品牌区＋表单区的非对称双栏，移动端折叠为单列。
- 删除 `admin123` 密码占位提示和默认用户名填充；保留登录后的默认密码安全提醒。

### 3. 三个核心界面

#### 运营总览

- “总余额”和“今日消耗”为两个一级指标。
- 将低余额、查询异常、日均消耗和预计耗尽整合为紧凑健康摘要。
- 图表和资源摘要形成清晰的主次层级，不再使用等权 KPI 卡矩阵。
- 保留刷新、趋势查看和现有数据口径。

#### 上游资源

- 页面名称和说明改为业务语言，连接器类型降级到详情或配置层。
- 桌面使用结构清晰的分区列表；移动端沿用已完成的专用卡片，并套用新品牌令牌。
- `NA / KEY` 方块、彩色 Tag 和图标动作降噪；状态改为“色点＋文字”。
- 保留新增、编辑、删除、刷新、固定成本和趋势详情的全部能力。

#### 登录页

- 作为首要品牌信任入口完成全量重构。
- 表单错误直接、克制，不使用营销话术或感叹号。
- 保证密码管理器、键盘操作、错误提示和移动端安全区域可用。

### 4. 产品语言与外围触点

- 更新全部页面标题、导航、说明、操作反馈和路由 metadata。
- 更新测试通知、Webhook source、推送分组、邮件发件人示例和通知签名。
- 更新 HTML 日报头尾签名、服务启动日志、PWA 名称与图标、缓存名称。
- 新增统一的加载、空状态、错误、无权限、404 页面。
- 系统设置页面移除 Ant Design Pro / MySQL 宣传式描述，新增系统信息区。

### 5. 其余页面首发处理

- “自营业务”“用量分析”“成本与利润”“告警中心”“系统设置”完成命名、主题令牌、排版和状态组件迁移。
- 首发不大幅重写这些页面的数据结构；深度版式重构放到第二阶段。

## 第二阶段

- 自营业务、用量分析、成本与利润、告警中心的深度信息架构重构。
- 首次部署引导、连接器配置向导和更完整的无障碍图表数据表。
- Open Graph 分享图、对外文档、Docker 镜像、容器名和 package name 的全面迁移。
- 微动效、品牌纹理和定制空状态插图。
- 内部缓存键、SMTP HELO 等低可见技术命名清理。

## 明确不做

- 不修改数据库 schema、API 路由、认证协议、告警计算和成本利润算法。
- 不删除连接器表单中的 New API / Sub2API 准确术语。
- 不迁移 Next.js、Ant Design 或图表库。
- 不在首发中修改现有页面 URL。
- 不移除原许可证、版权声明或必要的开源归属。
- 不将移动端响应式任务的未提交改动并入本任务。

## 可访问性与响应式要求

- 正文辅助信息不低于 12px；核心信息不低于 14px。
- 移动端主要操作触控区域至少 44×44px。
- 键盘焦点清晰可见；导航、菜单、表单和弹层可完整键盘操作。
- 状态不得仅靠颜色表达，必须同时提供文字或图标。
- 浅色和深色主题均满足正文与关键控件的对比度要求。
- 视口 375、390、768、991、1280、1440px 不产生页面级横向滚动。
- 尊重 `prefers-reduced-motion`，动效只使用 `transform` 和 `opacity`。

## 验收标准

1. 登录页、运营总览和上游资源三个关键页面完成设计与实现，并通过桌面/移动视觉验收。
2. 所有导航和页面主标题使用批准后的产品语言，现有路由与功能保持可用。
3. 浅色、深色、PWA 图标与浏览器标题使用同一品牌系统。
4. 日常用户可见界面、通知、邮件和日报中不再出现 `relay-monitor`、`中转站余额监控` 或技术栈宣传；许可证和内部技术标识例外。
5. 不再使用通用折线图 logo；品牌 SVG 在 16、32、192、512px 下清晰。
6. 三个核心页面不再呈现默认 ProLayout / 等权 ProCard 模板结构。
7. `npm test`、`npm run build` 和 `git diff --check` 全部通过。
8. 使用可连接数据库的本地或预发布环境完成真实登录后的桌面/移动截图验收。
9. 品牌改造不能回退现有移动端任务已经解决的布局和触控问题。
