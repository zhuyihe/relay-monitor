# 移动端响应式适配（查看优先）

## 范围决策

用户已确认采用 **B：查看优先模式**。

本期保证手机和平板浏览器能够登录、导航、查看监控数据、切换统计范围、浏览图表和表格、打开余额趋势。新增、编辑、删除及系统配置等管理流程不在本期做完整移动端适配，后续另立任务。

## 背景

当前面板以桌面端为主要使用场景。部分页面已经使用 Ant Design 响应式栅格或允许内容换行，但尚未形成完整的移动端体验，窄屏下仍可能出现导航不便、页面头部拥挤、站点信息错位、表格撑宽页面、图表标签冲突等问题。

本任务在不改变业务逻辑和数据口径的前提下，让现有 Web 面板在移动端完成核心监控查看流程，同时保持桌面端体验不回退。

## 目标

1. 320px 及以上视口可以登录并访问全部导航页面。
2. 总览、中转站、我的站点、用量统计和经营分析在移动端可以正常阅读和操作查看类控件。
3. 页面根节点不产生横向滚动；宽表只允许在自身容器内横向滚动。
4. 复用 Ant Design / Pro Components 的断点和 ProLayout 移动端 Drawer，不另造导航体系。
5. 保持深浅主题、数据请求、权限校验和后端 API 不变。

## 本期范围

### 1. 登录与全局壳层

- 登录卡片在 320px 宽度下保留安全边距，输入框、错误提示和登录按钮不溢出。
- 使用 ProLayout 现有移动端 Drawer；菜单切换后正确关闭并高亮当前页面。
- 移动端减少内容区外层留白，避免侧栏、头部或页面容器挤压正文。
- 顶部主题切换、全量刷新和用户菜单保持可触达。
- 页面标题和副标题先展示；筛选器、刷新时间、刷新按钮等操作移入可换行的独立工具栏。

### 2. 总览

- KPI 卡片按窄屏宽度切换为单列或两列，金额和单位不被截断。
- 总余额趋势和今日消耗图在移动端单列展示并随容器重绘。
- 站点摘要按“名称与状态、核心金额、次要信息、查看入口”的顺序重排。
- 长名称、域名、状态和错误信息不能只依赖鼠标悬停查看，应允许展开、复制或通过显式详情入口查看。

### 3. 中转站查看与余额趋势

- 站点列表在手机上保持明确的信息层级，金额、状态、趋势入口不会无序换行。
- 支持单站刷新和打开余额趋势；编辑、删除和新增流程不作为本期移动端验收项。
- 趋势弹窗位于视口安全区内，时间范围、KPI、图表和关闭入口可操作。
- 对现有管理按钮只要求不遮挡查看内容；不为其表单和确认流程做完整移动端重构。

### 4. 数据密集页面

覆盖“我的站点”“用量统计”“经营分析”：

- 时间范围、站点选择、刷新等查看类控件在手机上按固定顺序换行。
- KPI 卡片和图表在窄屏下切换为单列或两列，不造成根节点溢出。
- 表格在组件内部横向滚动，关键识别列优先显示。
- 热力图、饼图、双轴图和长图例允许在移动端降低标签密度、将图例移到底部或隐藏冲突外标签；完整信息通过触屏 Tooltip 查看。
- 覆盖空、加载、错误和正常四种状态。
- `/my` 中管理员 Key 管理、手工添加 Key、日志精算执行等管理流程不作为本期移动端验收项；其结果数据区域仍需可阅读。

### 5. 通知与设置页面的基础显示

- 页面能够通过移动导航进入，标题、卡片和已有数据不撑破视口。
- 通知渠道列表和设置项具备基本可读性，不遮挡页面导航。
- 新增/编辑/删除通知渠道、告警规则保存、账号密码修改及相关弹窗不在本期完整移动端适配范围。

## 非目标

- 不做原生 App、PWA 离线能力或独立移动站点。
- 不新增业务功能、通知渠道或数据指标。
- 不完整适配站点新增/编辑/删除、管理员 Key 管理、通知配置、告警规则、系统设置和密码修改流程。
- 不修改后端接口、数据库结构、认证方式或部署结构。
- 不进行品牌或整体视觉重设计。
- 不引入新的响应式框架、状态库或大型通用组件体系。
- 不用全局 `overflow-x: hidden` 掩盖布局错误。
- 除非现有工具无法完成验收，不引入新的端到端测试依赖。

## 实施顺序

1. 捕获所有路由 1440px 桌面端基线截图。
2. 统一使用 Ant Design 断点和 ProLayout 内置 Drawer，建立最少量的响应式 CSS 类或断点 Hook。
3. 处理全局壳层、页面边距、标题与工具栏。
4. 处理总览、站点列表和余额趋势弹窗。
5. 处理我的站点、用量统计和经营分析的筛选器、KPI、图表及表格。
6. 处理登录页，以及通知/设置页的基础可读性。
7. 逐阶段执行移动端验证，最后完成视口、断点、主题和桌面回归矩阵。

## 验收矩阵

### 全路由尺寸

- 320 × 568：最小支持宽度。
- 390 × 844：主要手机验收尺寸。
- 768 × 1024：平板竖屏。
- 1440 × 900：桌面回归。

### 抽查尺寸

- 375 × 812：总览、中转站、趋势弹窗和登录页。
- 812 × 375：手机横屏和短高度场景。
- 767 / 768 / 769px：ProLayout 手机/桌面边界。
- 991 / 992 / 993px：`lg` 图表分栏边界。

### 浏览器

- Android Chrome。
- iOS Safari。
- 桌面 Chrome。

## 客观验收标准

### 布局与交互

- 每个验收路由满足：`document.documentElement.scrollWidth <= document.documentElement.clientWidth`。
- 表格横向滚动时，页面根节点横向位置保持不变。
- 禁止通过全局裁剪隐藏不可访问内容。
- Drawer 可以打开、切换全部菜单，并在导航后关闭；当前菜单项正确。
- 主题切换、全量刷新、用户菜单、单站刷新、时间范围、站点筛选和趋势入口的点击区域不小于 `40 × 40px`。
- 纯图标按钮提供 `aria-label`；查看类关键操作在移动端具有文字或明确可访问名称。
- 弹窗矩形位于视口安全边距内；内容超高时正文区域可纵向滚动，关闭入口始终可触达。
- 软键盘弹出后登录表单仍可提交；输入聚焦不会触发非预期页面缩放。

### 图表与表格

- 图表随容器宽度重绘，不被容器裁切，不造成根节点横向溢出。
- 饼图、热力图、双轴图和长图例在 320px 下无重叠到不可识别的标签，触屏 Tooltip 可以展示完整值。
- 所有宽表具有局部横向滚动，长模型名和用户名不会撑宽根页面。
- 使用超长站点名、域名、错误信息、模型名、用户名、多标签和多行表格数据进行压力验证。

### 状态与主题

- 总览、中转站、我的站点、用量统计和经营分析覆盖空、加载、错误、正常状态。
- 390px 和 1440px 下对所有路由执行深浅主题检查；其他尺寸抽查核心页面。
- 1440px 下保存改造前后截图，确认导航结构、卡片层级和主要数据没有布局回退。

### 功能回归

- 登录、退出、导航、主题切换和全量刷新正常。
- 总览和站点列表数据可读，单站刷新和余额趋势可用。
- 我的站点、用量统计和经营分析的查看类时间范围与筛选可用。
- 通知与设置页面可以进入且基本内容可读；其管理流程继续由桌面端完成。
- `npm run build` 和 `npm test` 通过。

## 返工补充：移动端中转站卡片

### 问题结论

首版实现只解决了横向溢出，没有形成适合手机扫描的信息结构。移动端卡片继续承载全部桌面字段，并通过自动换行堆叠，造成正文列过窄、金额与操作缺乏稳定锚点、单站高度过高。

### 范围

本轮只返工 `/stations` 的移动端页面头部、站点列表和站点卡片。桌面端站点布局、站点数据计算、刷新接口、趋势弹窗和其他路由保持不变。

### 移动端信息结构

普通站点卡片按以下顺序展示：

1. 顶部：站点图标、站点名称、核心状态、人民币余额。
2. 身份信息：站点类型、账号、最后查询时间；延迟作为低优先级信息。
3. 摘要：今日消耗与预计可用时间，两列展示。
4. 趋势：48 小时迷你图独占可用宽度。
5. 底部：明确的“查看趋势”入口与单站刷新。

固定成本站点使用相同视觉骨架，但核心金额显示日均摊销，不展示趋势入口。

### 移动端操作策略

- 隐藏页面头部“添加中转站”。
- 隐藏站点卡片中的编辑和删除按钮。
- 保留全量刷新、单站刷新和查看趋势。
- 桌面端继续展示添加、编辑和删除，不改变管理能力。
- 不使用仅靠 `title`/hover 才能理解的移动端交互。

### 内容压缩规则

- 移除卡片中的“点击查看趋势”提示文字，由显式趋势入口承担说明。
- 名称最多两行；余额始终完整显示且不与名称争抢同一文本列。
- 元数据最多两行，长账号或错误文本允许安全换行；完整错误信息可通过趋势/详情入口查看。
- Token 数量作为今日消耗的次要说明，不单独占据主行。
- 延迟不作为第一视觉层级。

### 可量化验收

- 320px 视口下，成功状态的普通站点卡片目标高度不超过 190px；包含长文本时不超过 220px。
- 320 × 568 视口在页面头部之后能够看到至少一个完整站点和下一个站点的标题区域。
- 图标、名称/状态和余额位于同一顶部视觉区域，余额不换行、不截断。
- 今日消耗与预计可用时间在 320px 下保持两列；极长内容允许列内换行但不得撑宽页面。
- 迷你趋势图宽度随卡片变化，不使用固定 170px 布局挤压正文。
- 移动端不显示添加、编辑、删除；刷新与趋势入口点击区域不小于 `40 × 40px`。
- `/stations` 在 320、375、390、767px 下满足根节点无横向溢出。
- 768px 和 1440px 桌面布局与返工前桌面基线保持一致。
- 长名称、长账号、错误状态、无趋势数据、固定成本五种数据场景均需检查。
